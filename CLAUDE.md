# CLAUDE.md — Developer Guide for LLM agents

This file describes the `kelp` package internals so an LLM can continue development without re-reading every source file. It records **non-obvious** facts: conventions, cross-module contracts, gotchas. Plain API details live in the docstrings — read the module when you need them.

## What this project is

A Python Lagrangian particle tracker for unstructured ocean meshes, reimplementing Fortran tracer models. Status:

- **2D surface tracking** — complete; validated against the Fortran reference (forward + backward, < 1 mm) while both used 111 300 m per degree — since the switch to 111 120 the comparison test is skipped (~11.6 m systematic offset after 2 h at 1 m/s, see the Fortran section).
- **3D vertical tracking** — FESOM2 z-levels (direct W input) and FESOM-C sigma coordinates.
- **Stochastic diffusion** — uniform Kh / Euler-Maruyama / Milstein, wired into Euler/RK2/RK4 via three composition modes (split / combined / split_rk), counter-based RNG; **vertical Az** (TODO 2.2b, 3-D only) — split kick with mandatory Itô drift (Visser 1997) + reflective boundaries, `az_const` everywhere / `var_az` field FESOM2 z-level, `COMP_VERTICAL=1`.
- **Time-aware RK2/RK4** — stages lerp velocity to substep times on non-autonomous flows; opt-in 4-snapshot PCHIP in time (`numerics.temporal_reconstruction`); adaptive **RK45** (Dormand–Prince, 2-D element leastsq).
- **u/v interpolation** — `leastsq` (default), `barycentric` (node layout: HEALPix, NEMO, FESOM2 `unod`/`vnod`), `edge_leastsq` (FESOM-style).
- **HEALPix** reader (2-D + 3-D, dual or pixel geometry, regional extracts) and **NEMO** (2-D, E/N-aligned grids) besides FESOM2 and FESOM-C.
- **Offline W reconstruction** (`w_reconstruct.py`) from u, v, ssh.
- **Per-particle FailureReason diagnostics** — why each particle died.
- **Beaching model** (TODO 2.2) — 4 combinable criteria (depth/coastal_element/on_failure/stochastic), tidal resuspension (never/auto/stochastic/auto_or_stochastic), Fortran fix_* freeze via the alive-mask.
- **Field sampling along trajectories** (TODO 2.4) — T/S/any node-based scalar sampled at record points, written to trajectory output; standalone `sample_field` API.
- **Rotated-frame tracking** (FESOM2 + HEALPix, opt-in `mesh.rotation`) — Euler-rotated sphere (default `None` byte-identical; `"fesom2"` = (50,15,−90)); transpolar-capable, geographic output, frame-validated restart.
- **FESOM-style elemental interpolation + element tracking** (reviewer items, 2026-07) — `uv_interp: edge_leastsq` (LSQ over the containing element + its edge neighbors; boundary ghosts per `edge_leastsq_bc: freeslip|noslip`); `elem_search: walk` (containing element searched ONCE at release, then tracked across edges; verdict-identical to the per-step scan, unfused paths, ~3.6× faster containment); quad vertex weights = guard-free product-form Wachspress (convex quads are a mesh contract).
- Streaming trajectory output (NetCDF **and Zarr**, both readable mid-run — Zarr is lock-free, NetCDF via `numerics.output_flush_every`; **output format 2**: CF trajectory layout with a calendar `time`, release positions/times, velocities NaN outside ALIVE steps) with restart checkpoints, temporal velocity interpolation, installable package (`pip install -e .`), `kelp` CLI (`run` / `info`).
- Performance: measured rows live in `benchmarks/` and `docs/performance.md` (the old "15–19× faster than Fortran" figure has no measurement in this repository).

## Running an experiment (start here for a new run)

To turn a described experiment into a runnable setup, do NOT re-derive
capabilities from the source — the mechanics are already written down:

- **Skill `kelp-run`** (`.claude/skills/kelp-run/SKILL.md`) — the entry
  point: a described task (release location, forward/backward, surface/3D,
  diffusion, beaching, T/S sampling, time window) → **seeds + config + run
  command**. **Skill `kelp-config`** — the YAML-writing mechanics.
  **Skill `kelp-experiment`** — the campaign layer for a **big / long /
  big-mesh** experiment (millions of particles, runs that outlive one allocation,
  region cropping): the order-of-operations (isolate clone → crop+validate →
  wait-for-extraction → probe → load-probe → resumable dependency chain) and the
  setup pitfalls to avoid. The other skills: **`kelp-analysis`** (reading
  trajectory output at the writer's chunking; cohort statistics, denominators,
  censoring, timing numbers), **`kelp-visualize`** (figures, montages,
  videos; the figure contract), **`kelp-diagnose`** (a run slower than
  documented, silent, or scaling oddly — the diagnosis path BEFORE any code or
  config change), and **`kelp-bench`** (the portable benchmark row per
  machine).
- **`docs/configuration.md`** — authoritative option-by-option reference
  (defaults, validation, file-discovery rules, pitfalls). **`docs/architecture.md`**
  — the config→reader→mesh→loop→writer pipeline.
- **Ready templates** — `examples/config_*.yaml` (genericized real runs):
  `config_global_2d_10yr.yaml` (2D, multi-year, node velocities, pulsed release,
  rotated frame), `config_global_2d_1yr.yaml` (simpler), `config_weddell_3d.yaml`
  (3D, W + T/S sampling), `config_nemo.yaml` (structured C-grid),
  `config_healpix_2d.yaml` / `config_healpix_3d.yaml` (HEALPix stores). Copy and
  set the paths.
- **Tools** — `utils/extract_fesom_region.py` (crop a region/years → Zarr; the
  memory lever for big meshes so 3D / 4-snapshot reconstruction fits in RAM);
  `utils/reconstruct_w.py` (offline W when a dataset lacks vertical velocity);
  the full list is in `utils/README.md`.
- **Mesh ≠ data**: the mesh diagnostic (`fesom.mesh.diag*.nc` / dir / Zarr) and
  the model output normally live in *different* directories — set both.
- **Data shapes seen in practice** (no fixed locations — set paths per run):
  *FESOM2* multi-year output is one file per variable per year
  (`<var>.fesom.<year>.nc`); a single run cadence must be consistent, so pick
  one family — node velocities `unod`/`vnod`/`w` (+ `temp`/`salt`/`ssh`) are
  often **daily**, while element `u`/`v` may be **monthly**; the mesh is a
  FESOM2 `fesom.mesh.diag.nc` (core2/`.comp`/UGRID conventions auto-detected).
  *FESOM-C* is a single coastal NetCDF (sigma coordinates).
  *HEALPix twins* (validation-grade): combined one-year stores with daily node
  `uo/vo/wo/ssh/temp/salt`, self-contained incl. the vertical table; the tests that
  use them read the directory from `KELP_TEST_DATA` (see `tests/test_healpix_real_core2.py`).

## Module details

### core/config.py
- `load_config(path) → AppConfig`; sections `mode`/`numerics`/`mesh`/`data`/`time` → dataclasses. Unknown YAML keys silently ignored; an empty section (`mode:` = YAML null) loads with defaults. Load-time checks (2026-10-04) also cover `mode.time_dir ∈ {1, -1}` (stored float), `sigma_layer` + `sigma_mean` together (refused), `numerics.integrator` (`_VALID_INTEGRATORS` == `integrators.INTEGRATORS`, pinned) and `w_interp` (`_VALID_W_INTERP` == `vertical._W_METHOD_MAP`, pinned), `data.time_averaging`, quoted strings where a list is expected (`periodic_*`, `crop_bbox`), and empty `numerics.diffusion:`/`beaching:` blocks (→ defaults).
- `NumericsConfig.dt: Optional[float] = None` — auto-detected from the file time coordinate when omitted.
- `NumericsConfig.w_interp = "leastsq"` — `"nearest" | "leastsq" | "barycentric" | "idw"`. Fused 3D Euler supports nearest/leastsq only; others use the unfused path.
- `NumericsConfig.diffusion: DiffusionConfig` — see below.
- `ModeConfig.max_levels: Optional[int]` — in 3D: number of vertical interfaces kept from the surface down.
- `ModeConfig.w_positive = "auto"` — `auto|up|down`, the sign convention of the vertical velocity IN THE FILE (validated, lower-cased). Internal `VelocityField.w` is always positive-down; readers convert via `readers.resolve_w_sign` (`auto` → CF `positive` attr → CF `standard_name` upward_/downward_ → reader default: fesom2/fesomc/healpix `up`; `utils/reconstruct_w.py` output stamps `positive="down"`).
- `ModeConfig.sample_vars: list[str]` (default `[]`) — dataset variables sampled along trajectories; a single YAML string is coerced to a list, `null` → `[]`. Empty = sampling fully dormant (byte-identical output).
- `NumericsConfig.sample_interp = "leastsq"` — `"nearest" | "leastsq" | "barycentric" | "idw"`, validated at load.
- `NumericsConfig.uv_interp = "leastsq"` — `"leastsq" | "barycentric" | "edge_leastsq"`, validated at load; non-leastsq = unfused integrator paths, EXCEPT node-layout barycentric with `vel_next` (fused bary-tinterp kernels; certificate-gated only with `mesh.exact_nearest: false` — see integrators section). `edge_leastsq` = FESOM-style fit over containing element + edge neighbors (element layout only, like leastsq).
- `NumericsConfig.edge_leastsq_bc = "freeslip"` — `"freeslip" | "noslip"`: boundary-ghost value for `edge_leastsq` (mirror of centroid across the boundary edge carries the mirror IMAGE of u_own — tangential kept, normal reversed — / `−u_own`; the old freeslip copied `+u_own`, a zero-gradient ghost that let flow cross the coast, fixed 2026-09-23); inert for other uv_interp methods.
- `NumericsConfig.elem_search = "local"` — `"local" | "walk"`: containing-element search. `walk` = search once at release, then cross edges (docs/localization.md §7); verdict-identical to local (fallback chain), unfused paths only (walk+leastsq warns once).
- `MeshConfig.r_earth: Optional[float] = None` — Earth radius (m) for mesh-derived areas/metrics; validated `> 0` when set. `None` → reader family default (FESOM2 `6_367_500`, FESOM-C `6_400_000`); set explicitly only to match a model build with a non-default radius. Flows into `Mesh.r_earth`: the spherical-excess area fallback and the local projection of the barycentric cores and fused barycentric kernels use it (value-neutral there: it cancels in the weight ratios).
- `MeshConfig.grid_hash_cell_size: Optional[float] = None` — nearest-node grid-hash cell in degrees; validated finite in `(0, 45)` when set (string/number coerced to float, bool refused; `set_grid_hash_cell` applies the same bound — a 60° pin used to pass and break the next rebuild, 2026-10-04). `None` → the automatic rule below. Applied reader-agnostically by `run_tracking` right after `load_mesh` via `core.mesh.set_grid_hash_cell` (pins `mesh.metadata["grid_hash_cell"]` + rebuilds). See the `build_search` bullet for when it matters.
- `MeshConfig.grid_hash_cell_rule: str = "occupancy"` (`"occupancy" | "legacy"`, validated lower-cased; inert when `grid_hash_cell_size` is set) — **2026-09-22**: the automatic cell is CHOSEN BY MEASUREMENT, not by the mesh-wide mean spacing. `run_tracking`, `track_particles(grid_hash_cell_rule=)` and `kelp info` call `core.mesh.apply_grid_hash_cell_rule(mesh, rule)` AFTER `set_exact_nearest` (the mode depends on the flag), in the else-branch of the explicit-cell path (an explicit `grid_hash_cell_size` is pinned instead and reported `explicit`); `load_mesh`/`build_search` still build the LEGACY cell (library users and the synthetic test meshes keep it — a direct driver applies the rule itself). `choose_grid_hash_cell(mesh, *, exact=None, sample=200_000, seed=0, min_median=8, approx_tol=0.005, max_far_rows=64, steps=12, min_gain=2.75, max_unprovable=0.20, max_hash_mb=128.0)`: ≤ 200k sampled element centres (deterministic; non-finite centres dropped; Numba required — without it the reader's cell is kept), their exact nearest node ONCE through `_grid_hash_nearest_batch(..., exact=True)` (cell-independent θ/cap extent), then per candidate `legacy/√2^k` without rebuilding the hash: node counts per cell (`_gh_lon_branch`/`_gh_grid_geometry`/`_gh_cell_index` — the build's arithmetic factored out, pinned bit for bit), a 2-D prefix sum, and the prange `_gh_sample_stats` → 3×3 occupancy, the widening share (the search's OWN certificate `_anchor_provable_rect(rx=ry=1)` on the window, plus empty windows and windows without the true nearest — the uniform-coverage bound over-counted 7.4 % vs 3.8 % on CORE2, review 2026-09-22), approximate share (true nearest OUTSIDE the window — the guard-off risk), and the scan-cost proxy (provable: occupancy + 9 cells + one certificate; else the certificate's rectangle node count + the cells the growth visits `9 + rx·(2ry+1) + 2ry` (all columns: `9 + 2ry`) + one certificate per growth iteration; counting cells is what stops a cell far below the spacing from looking free). Proxy weights `_GH_COST_CELL = 1`, `_GH_COST_CERT = 20` (one certificate evaluation per growth iteration, `max(rx, ry) + 1`; calibrated against the measured exact batch search per candidate cell on CORE2 and the 80–88 °N structured mesh — without it the argmin sat one ladder step below the measured optimum). Mode `exact` → argmin mean cost (ties → larger cell) over the ELIGIBLE candidates — widening share ≤ `max_unprovable` (20 %) and hash offsets ≤ `max_hash_mb` (128 MB = 32 M cells; the legacy row is always eligible) — taken only if it predicts ≥ `min_gain` (2.75×), else legacy; `approx` (guard off) → smallest cell with empty == 0, median ≥ 8, approx ≤ legacy + tol, hash ≤ `max_hash_mb`, else legacy. The eligibility bounds are the proxy's validity domain (review 2026-09-22: on the 11.5 M-node global mesh the argmin was the cap-limited LAST candidate, 46 M cells = 185 MB of offsets per process, 21 % widening, predicted 5.9× where 1.4–3.1× was measured; bounded, the rule takes 0.0513° = 92 MB, predicted 4.9×, measured 1.7–2.6×). Hard limits `_gh_far_rows_for ≤ 64`, `nx·ny ≤ _GRID_HASH_MAX_CELLS`; per candidate the transient is `counts` (int64) + an int32 in-place prefix sum (no axis-0 temporary). `apply_grid_hash_cell_rule` pins a different choice via `set_grid_hash_cell` (which itself stamps `grid_hash_cell_rule = explicit`), stores `mesh._gh_report`, stamps `metadata["grid_hash_cell_rule"]` + `grid_hash_cell_mode` (exact/approx); `build_grid_hash` drops a report that describes another cell. Reused mesh: an explicit pin is never overridden (reported `explicit`); the same rule+mode returns the earlier report (no second ladder for a `track_particles` loop); a different rule or mode after an earlier `occupancy` pops that pin, rebuilds the reader's cell and decides afresh (`legacy` after `occupancy` restores the reader's cell; the strict guarantees never inherit an exact-mode cell). `describe_grid_hash(mesh)` = the one-line report (run verbose + `kelp info`). Writer metadata ALWAYS: `grid_hash_cell` (resolved, float) + `grid_hash_cell_rule` (occupancy/legacy/explicit) — an old run is repeated by pinning that value or `legacy`. NOT byte-identical to legacy at exact ties (scan order breaks them) and for guard-off anchors; the synthetic run_tracking fixtures ARE identical (pinned). Exact mode deviates from legacy only for a predicted gain ≥ `min_gain` = 2.75×, the mid-gap between the two calibrated classes (`benchmarks/grid_hash_cell_rule_table.md`, 2026-09-22): QUASI-UNIFORM meshes predict 2.0–2.2× (HEALPix CORE2 twins z6/z7/z8 2.03–2.06, CORE2 2.16) — a smaller cell buys ~1.6× on the search in isolation, nothing measurable on the step of a global release (CORE2, 60 daily steps × 200k: 93–97 ms at the legacy cell vs a mean of 97 ms at half of it) and measurably costs at high latitude (HEALPix 80–88 °N +17–24 %, land-cap seeds ×3.5) — so they KEEP the reader's cell; STRUCTURE-RESOLVING meshes predict ≥ 3.6× (FESOM-C `sns_multi_m8` 3.6 → 0.058° → 0.014°, window 207 → 13, search 1.7×; the 11.5 M-node global mesh 4.9 → 0.145° → 0.051°, search 1.7–2.6×; the synthetic estuary (ratio 100) 0.05° → 0.0016°, strip cost ÷ 30, ×26 measured). The proxy's own error is up to ~2× across meshes and hardware (measured/proxy 0.45–1.85 ‰), hence the margin. A release confined to a refined region still wants the explicit cell (CORE2 Arctic at 0.5°: −28 % per step on the Beaufort run; the rule samples the mesh, so it predicts CORE2's global 2.15–2.16 and keeps 1.38°). The sample is the MESH, not the seeds (a coarse-region release may prefer an explicit cell; `utils/check_grid_hash_cell.py` probes seeds and prints the rule's line too).
- `MeshConfig.exact_nearest: bool = True` (guard added 2026-09-12, default ON since 2026-09-14; `false` + `grid_hash_cell_rule: legacy` = pre-guard anchors bit for bit — since 2026-09-22 the default rule may change the cell in strict mode too) — exact nearest-node anchor guard: `run_tracking` → `core.mesh.set_exact_nearest(mesh, True)` (`mesh.metadata["exact_nearest"]`, survives hash rebuilds); `find_nearest_nodes` then runs the batch kernel in exact mode (`_grid_hash_nearest_batch(..., exact=True)` → the in-kernel exact search `_grid_hash_nearest_exact` per query; the KD heal is reached only on an empty mesh). Zarr: `time` attrs set later survive block flushes (pinned).
- Lazily creates the int8 `failure_reason` variable (CF `flag_values`/`flag_meanings`; on the Zarr backend too since 2026-10-04, set on the live `create_array` handle, as are the `status` flags) when `state.failure_reason` is set; `vel_u/vel_v` (when a record carries `u`) and `vel_w` (when a record carries `w` — never in 2-D) are created lazily and INDEPENDENTLY — except that `run_single_realization` declares them up front (`TrajectoryWriter.declare_velocity(w=Fdrift3D)`, review 2026-10-14): a segment resumed when every particle is dead records no velocity and, lazily, lacked the variables, which `concat_trajectories` refused. Once a lazy var exists, every record writes it: the provided value or its fill column (explicit in NetCDF; the format-1 NetCDF had no `_FillValue`, so an unwritten velocity record read 9.97e36).
- `append(state, t, sampled=None)` — `t` = the record label in seconds (format 2: both modes; tracking computes it, see the tracking bullets). Sampled scalars become lazy `f8 (trajectory, time)` vars with `_FillValue=NaN` (late creation NaN-backfills earlier records; Zarr: attrs must be set on the live `create_array` handle — a later `resize` drops attrs set via transient `store[name]`), plus `coordinates` and a `comment` on the sampling instant. Reserved names (`_RESERVED_VAR_NAMES` + `restart_*`) → ValueError. `TrajectoryWriter(..., sample_var_attrs=)` carries units/long_name. Checkpoints never store sampled values. `load_trajectories` discovers any extra `(trajectory, time)` or `(trajectory, obs)` var generically.
- **Restart block is LAZY + crash-safe (format 2)**: no `restart_*` variable exists until the first `write_checkpoint` (`_ensure_restart_block`, both backends) — it creates `restart_valid` FIRST and writes 0 (NetCDF: `sync`) before any payload variable, then the payload, then 1 (the clear-first/set-last order of 2026-09-23 now covers the first checkpoint too). Format 1 created the block at `open()` (9.97e36 NetCDF / 0 Zarr without a checkpoint).
- `load_restart(path) → {"state", "step_i", "file_idx", "wet_streak", "rotation_angles", "release_step", "particle_offset"}` (state includes `failure_reason`/`release_step`/`elem`/`release_lon/lat/z` if stored; `wet_streak`/`rotation_angles`/`release_step` None when absent); raises `ValueError("No valid restart checkpoint in …")` if no valid checkpoint — a missing flag or a NetCDF flag created but never written (masked) is invalid (`np.ma.filled(flag, 0) != 1`). `write_checkpoint(state, step_i, file_idx, wet_streak=None, rotation_angles=None, release_step=None)` — lazy `restart_wet_streak`/`restart_release_step`/`restart_elem` (elem read off `state.elem` directly) int32, `restart_release_lon/lat/z` f8 (read off `state.release_*`, MESH frame) + scalar `restart_rotation_alpha/beta/gamma` attrs (only when set/rotated), both backends.
- `write_restart_file(path, state, step_i, file_idx, *, wet_streak=None, rotation_angles=None, release_step=None)` — **module-level** (not a `TrajectoryWriter` method): writes a **standalone** NetCDF restart (same `restart_*` schema as `write_checkpoint`, so `load_restart` reads it identically), but as its own self-contained file rather than embedded in a trajectory output. Use it to drop **one numbered, kept restart per checkpoint** (`restart_step<NNN>.nc`) into a dedicated dir for a **resumable-chain** driver (the embedded `write_checkpoint` only ever holds the latest, overwritten each call). `release_step` falls back to `state.release_step`; stores `restart_release_lon/lat/z` from the state; raises ValueError when a per-particle array's length ≠ `len(state.lon)`. The resumable-chain pattern (segment outputs + numbered restarts + resume + concat, for compute-time-limited jobs) is the subject of docs/io_and_time.md §6.
- `load_trajectories(path) → {"lon","lat","z","status"} (P,T), "time" (T,) raw seconds, "trajectory" (P,)` plus `failure_reason` / `vel_*` / sampled vars / `release_lon/lat/z/time` (P,) when present; reads both layouts (`(trajectory, obs)` format 1, `(trajectory, time)` format 2), masked values → NaN.
- **Mid-run readability / flush cadence**: a NetCDF4 (=HDF5) file holds an exclusive write lock while open, so it is unreadable by other processes until `close()` (and a hard-killed run leaves it un-closed). `TrajectoryWriter(..., flush_every=N)` (config `numerics.output_flush_every`, CLI `--flush-every`) makes the **NetCDF** backend buffer N records (copies) then open-append-close each batch (`_NetCDF4Backend._flush` via `_begin_write`/`_end_write`; `_flush_block` is the Zarr backend's) → no lock between flushes, **byte-identical output**; `0` (default) keeps the file open + `sync()` per append. The **Zarr** backend is lock-free (chunked objects) and **block-buffers**: record columns accumulate in RAM and flush one whole obs-chunk at a time (`_flush_block` → `arr[:, start:end] = block`), and the obs-chunk width is **adaptive** (`OBS_CHUNK_MAX=256` / `TARGET_CHUNK_BYTES≈4 MB`, computed from the trajectory-BLOCK size) — the old per-step single-column write recompressed a `(n_particles, 256)` chunk (~260 MB at 127k nodes) every step (no Zarr write cache) and ran 2×+ slower than NetCDF (development measurement, not recorded in the repository); both backends' `write_checkpoint`/`close` flush the buffer first, lazy vars back-fill to the on-disk length (`_flushed`). **Trajectory-axis blocks (TODO 5.4, 2026-08)**: above `TRAJ_CHUNK_MAX=500_000` particles the trajectory axis is split into 500k blocks (`chunks=(traj_chunk, obs_chunk)`), so a particle subset reads only its blocks (~4 MB chunks instead of a 63 MB full column at 7.9M); at or below the threshold the layout is the historical single block, byte-identical. The obs flush covers all blocks in one assignment (chunk-boundary flushes write each chunk once; a mid-buffer checkpoint / final partial buffer may rewrite the trailing chunk — pre-existing). Old outputs keep their layout — the analysis skill documents both read patterns.

### numerics/interpolate.py — CRITICAL MODULE
Numba `@njit` with graceful Python fallback (pattern repeated across all numerics modules).

`_interp_leastsq_core` — per-particle least-squares fit over elements around the nearest node:
1. element IDs from `node_to_elems`;
2. metric scaling `z0 = cos(yp·DEG2RAD) · METERS_PER_DEG_LAT`;
3. **centered coordinates** `ex = lon_elem·z0 − xp_m`, `ey = lat_elem·METERS_PER_DEG_LAT − yp_m` — eliminates the catastrophic cancellation that the absolute-coordinate Sarrus determinant suffers (see docs/interpolation.md §1);
4. symmetric 3×3 normal matrix + RHS in one loop; Sarrus determinant + Cramer;
5. value at the particle is just `a0` (dx=dy=0 in centered coords).

- `_interp_leastsq_core_fortran` — legacy absolute-coordinate kernel, kept only for comparison (has the cancellation bug).
- `_interp_leastsq_core_tinterp` — blends two snapshots inline per element (used by fused time-aware RK kernels). `_interp_barycentric_core_tinterp` — the NODE-layout barycentric twin: same nested two-level blend per VERTEX on the untouched bary geometry (no elem_hint, node layout only; consumed by `_fused_rk{2,4}_step_2d_bary_tinterp`).
- `interp_leastsq(state, mesh, vel, nn_nodes, time_dir=1.0, layer=0)` — `prange` loop over alive particles; `layer` is `int` (2D) or per-particle `np.ndarray` (3D, via `_loop_interp_leastsq_3d`).
- `interp_nearest_element` — fallback: containing element's value.

**u/v registry** (`get_interpolator{,_single}(name, edge_leastsq_bc="freeslip")` → vectorised / single-particle; unknown name raises with the valid list): `"leastsq"` maps to the untouched `interp_leastsq{,_single}`, `"barycentric"` to `interp_barycentric{,_single}` (`_interp_barycentric_core`), `"edge_leastsq"` to `interp_edge_leastsq{,_single}` (`_interp_edge_leastsq_core`; non-default bc → functools.partial).
- `_interp_edge_leastsq_core` — containing element (`_find_containing_element_local`) + edge-sharing neighbors (`build_elem_neighbors`) → 4-point (tri) / 5-point (quad) LSQ plane fit, particle-centered metric coords with WRAPPED lon deltas (dateline-safe; the default leastsq cores got their own gated antimeridian correction in 2026-07); boundary edge → ghost = own centroid mirrored across the edge, value = mirror image `2(u·t̂)t̂ − u` (freeslip) / `−u_own` (noslip); element layout only (node → ValueError in the wrappers); containment required → ok=False. Linear-exact in interior elements; freeslip keeps WALL-PARALLEL constants exact at the coast and damps the normal component. **noslip artifacts (documented, characterization-pinned)**: interior-side overshoot ~+60% in wall elements, sign reversal near two-wall corners — single-plane-fit property, not a bug. Sliver stencils stay conditioned (mirror ghosts span both directions; det/(a11·a22·a33) ~ 0.7 even at aspect 1e-4) — no scale-aware det guard needed.
- `_interp_barycentric_core` — containing element (`_find_containing_element_local`) → `_polygon_weights` vertex blend; vertex values: node layout = direct lookup, element layout = area-weighted average over `node_to_elems` (`build_elem_areas`). Projects to the local plane around the **element centroid** (not particle-centered) using `mesh.r_earth` (threaded from the wrappers; weights are scale-invariant so the value is R-independent — the arg only keeps the projection unit-consistent with the mesh metrics). Constants exact both layouts; linear exact node-layout only (element layout smooths). Containment required → `ok=False` reverts to OUTSIDE.

### w_reconstruct.py — offline W reconstruction (FESOM2 z-level only)
- **Variant A (divergence)**: `w(D) = −ssh_t − ∫ div_h dz`, weak-form shape-function divergence (approximate); Tier 1 constant surface area, Tier 2 depth-dependent `nod_area` from mesh diag.
- **Variant B (ALE heuristic)**: `w_cart ≈ w_ALE − (1−D/H)·ssh_t` — heuristic, not exact z-star physics.

**Diffusion dispatch** — each integrator accepts `diffusion=DiffusionStepArgs(...)` (None → byte-identical no-diffusion):
- *split* (uniform Kh, any integrator): deterministic step, then `_apply_split_diffusion_kick` adds the Brownian kick; re-validates, reverts failures to OUTSIDE; 3D z **reclamped** after the horizontal kick against the new local bottom. `_apply_split_az_kick` runs LAST on the split path (all three integrators): vertical Az kick + reflective fold, z-only (no re-validation needed); receives `time_dir` and passes the SIGNED dt (`time_dir*dt`) to the loops, whose kernel takes |dt| for drift and noise — tracking's dt is always positive (same convention as the em/m1 drift kernels); short-circuits (same object) when az off/zero-source; `az_requires_field` (set by tracking when `var_az` configured) → payload without `vel.az` raises instead of silently degrading to az_const; 2-D vel + az → ValueError backstop; sigma + `vel.az` field → ValueError (v1); em/m1 + az_enabled args → ValueError backstop at the top of all three step functions (those branches never reach the kick).
- *combined* (em/m1 + Euler): `_apply_combined_em_step` *replaces* the Euler step with the full SDE step; Kh/∂K sampled at the start position. **3D raises NotImplementedError.**; fails fast for uv_interp != leastsq or node-layout velocities (the drift kernel is element-centre leastsq)
- *split_rk* (em/m1 + RK2/RK4): deterministic RK first, then `_apply_split_rk_em_kick`; `kh_eval_position` picks the Kh sample point; `_pick_kh_eval_vel` lerps Kh to `sim_time + dt` when temporal-interp info is available. One-time RuntimeWarning per `(seed, real_id, scheme)` — pragmatic extension, not a rigorous SDE scheme. **3D raises NotImplementedError.**

**Time-aware mode** — for time-dependent velocity, RK stages must evaluate `u(x, t + c_k·dt)`:
- Pass `vel_next=` (raw snapshot the step moves TOWARD — next file snapshot forward, **previous** one backward) + `dt_to_next=` (positive seconds to it); stages materialize `vel.lerp(vel_next, c_k·dt/dt_to_next)` via `_make_stage_vels`, or blend inline in the fused `_fused_euler/rk2/rk4_step_2d_tinterp` kernels — sampling `t ± c_k·dt` along the motion. The fused kernels take the RAW bracket pair + `alpha0` (from `LazyLerpField`) and a SEPARATE stage-target array (`u_t/v_t` = `vel_next`, which equals bracket-B forward but bracket-A backward — fusing those roles broke backward tinterp once, pinned by tests now); the nested blend `(1-αk)·((1-α0)·A + α0·B) + αk·T` is bit-identical to stepping on the materialized field. Plain fields pass `alpha0=0`, collapsing to the old arithmetic exactly. Both tracking paths pass the direction-correct neighbour (tinterp via `_resolve_time_bracket(..., direction)` / `_build_vel_payload(..., direction)`: on-snapshot backward queries bracket downward, so e.g. a backward start at the LAST snapshot gets a real bracket instead of a steady downgrade).
- Rules: both kwargs or neither; `dt <= dt_to_next` (else ValueError); shapes of u/v/eta/w must match; Euler accepts them; its velocity ignores them (on sigma meshes they give the column's surface at the end of the step).
- **Convergence caveat**: the *linear* (default) lerp between snapshots caps time-order at O(dt²) regardless of RK order — RK4 collapses onto RK2 at coarse `file_dt`. Remedies: `dt << dt_to_next`, denser file cadence, or `numerics.temporal_reconstruction: pchip` (below).
- **PCHIP temporal reconstruction** (`numerics.temporal_reconstruction = "linear" (default) | "pchip"`, `numerics/temporal_reconstruct.py`): a 4-snapshot monotone-cubic (Fritsch–Carlson) blend in time, replacing the 2-snapshot lerp. **Opt-in, byte-identical when `"linear"`.** Active only with `temporal_interp: true` (else a one-time inert `RuntimeWarning`). Tracking resolves a 4-snapshot stencil (`_resolve_recon_stencil` on top of `_resolve_time_bracket`; interior+consecutive only — first/last interval and cycle seam fall back to linear with a one-time warning) and passes `recon=(snaps4, times4, q_time, direction)` to `rk2_step`/`rk4_step`. **2D least-squares routes to FUSED 4-snapshot-cubic Numba kernels** (`_fused_rk{2,4}_step_2d_pchip` → `_interp_leastsq_core_pchip4`, blending the Fritsch–Carlson cubic inline per element via the `@njit` scalar twins `_fc_slope_scalar`/`_pchip_value_scalar` — no per-stage full-field materialization). **3-D RK2 on node-layout barycentric z-level meshes** (`w_interp` nearest/barycentric, no walk) routes to its own fused kernel `_fused_rk2_step_3d_bary_pchip` (`_run_fused_rk2_3d_bary_pchip`); every other 3-D, node-layout or barycentric case keeps the **unfused** path (`make_stage_vels_recon` → `reconstruct_pchip` per stage, at `q_time + direction·c·dt`); the fused 2-snapshot linear tinterp kernels are still bypassed when `recon` is set. The fused and unfused results agree element-for-element (pinned by `test_fused_pchip_matches_unfused`, RK2/RK4 × fwd/back); `_run_fused_2d_pchip` re-validates the bundle (4 finite strictly-increasing times, matching `direction`/`time_dir` sign, equal snapshot shapes, every stage time inside the central bracket) for parity with `reconstruct_pchip`, which raises. No new extrema PER COMPONENT (Fritsch–Butland weighted-harmonic slopes; does NOT preserve linear constraints such as zero divergence, rotation equivariance or window means — review 2026-09-22); works in 3D (per-element blend of u/v/w/eta/scalars; Kh NOT reconstructed). Result: under PCHIP, RK4 separates from RK2 at coarse cadence (test_temporal_reconstruction.py). Euler ignores `recon`. **failure_reason** IS stamped on the fused PCHIP path too (since 2026-08-16, candidate 7 — every fused kernel). **Unfused whole-field blends are PARALLEL** (TODO 6.7, 2026-08): `_pchip_blend4` routes large same-shape C-contiguous fields through the `prange` kernel `_pchip_blend4_flat` (per-element `_pchip_value_scalar` → bit-identical to the numpy expression, which remains the fallback), and `make_stage_vels_recon` dedups stage times (RK4's midpoint pair reconstructed once; exact float-key cache, stage fields are read-only). Measured: one core2-size blend 953→46 ms @8thr (×20; ×47 @32); RK4 stage set ~275 ms @8thr — the old ~5–6.6 s/step N-independent floor is gone (docs/performance.md §2). Remaining limitation: 23M-mesh 3D holds 4 snapshots (memory — crop the mesh).

### tracking.py
- `TrajectoryRecord` — list-based snapshot storage (`.append(state, t)`, `.to_arrays()`, `.set_release(lon, lat, z, time)`); `times` are float SECONDS (the same labels the writer gets, both modes). - `run_single_realization(mesh, ds, reader, init_state, mode, numerics, start_time_idx, n_steps=None, n_time_total=None, on_exhausted="stop", verbose=False, shared_cache=None, *, end_time_idx=None, writer=None, checkpoint_freq=0, temporal_interp=False, file_times=None, file_dt=None, sim_time_start=None, realization_id=0, start_step_i=0, sample_vars=None, sample_interp="leastsq", output_sample_vars=None, start_wet_streak=None, particle_offset=0)`:

  - **Temporal-interp mode**: blends velocity between adjacent snapshots; `dt` may be smaller than the file step; uses `file_times` when given, else reads the axis from `ds` (`extract_time_info`) or builds it from `file_dt`. The payload is a `LazyLerpField` (never a materialized full-field lerp): on the 23M global mesh the old eager payload cost ~380 ms/step (numpy) / ~84 ms (numba `_blend`) (development measurement, not recorded in the repository); the lazy payload is ~1 µs + per-field blends only for consumers that read them.
  - `on_exhausted="stop"` breaks at the file boundary; `"cycle"` wraps via `% n_time_total`.
  - **Record clock (output format 2)**: the record after global step `g` is labelled `T_g0 + (g+1)·dt·direction` in seconds since the forcing's first RAW record (the `extract_time_info` origin; the `mean` shift moves values, not the origin), `T_g0` = the start of global step 0 (`_record_clock_origin`): interpolated → `t_first − start_step_i·dt·direction`, `t_first` = `sim_time_start` or `file_times[start_time_idx]` (exactly the `sim_time` init); discrete → the time of the record where global step 0 started, `_index_to_sim_time(start_time_idx − start_step_i·direction, axis, n_time_total, on_exhausted)` with `axis` = `file_times` or, for a direct caller that passed none, the dataset axis `_check_discrete_dt` reads (unshifted) — anchoring on the segment's own start record made the labels depend on the chain cuts when the spacing differs from `dt` within the check's tolerance; `sim_time_start` IGNORED in discrete mode (the reads follow `start_time_idx`); no axis → `(start_time_idx − start_step_i·direction)·dt` (then `on_axis` False → no epoch). `start_time_idx` must be whole (a float such as `start0 + n·time_dir` is cast; 2.5 → ValueError). The internal `sim_time` accumulator is untouched → positions bit-identical; labels are chain-cut invariant (a resume passes the SAME shifted `file_times` and, discrete + `cycle`, the UNWRAPPED start index — the checkpoint's `restart_file_idx` stores the unwrapped index in discrete mode, so `file_idx + direction` resumes too). Discrete labels are the particle clock: they may drift from the record stamps by `_check_discrete_dt`'s tolerance per step. - **nemo.py** (`@register("nemo")`, TODO 4.6 v1 = **2D, E/N-aligned grids only**): NEMO C-grid output → `structured.build_structured_mesh`. `load_mesh` reads `nav_lon/nav_lat` + `tmask` (surface) from `mesh.meshpath` (mesh_mask/domain_cfg; all-wet if no mask). **Alignment fail-fast**: NEMO grid_U/grid_V are along the LOCAL grid axes, not geographic E/N; v1 uses them as E/N, valid only on an aligned grid, so `load_mesh` computes the max i-axis-from-east / j-axis-from-north deviation (`_max_axis_misalignment_deg`) and raises `NotImplementedError` if > `_ALIGN_TOL_DEG`=2° (skewed/curvilinear/ORCA → needs vector rotation, the next PR). `open_dataset` assembles grid_T (`ssh`+sampled T-scalars) + the **derived** grid_U/grid_V siblings (swap the `grid_T` token in the basename; grid_V also via `ncinput_v`; **grid_W/`ncinput_w` are reserved for the 3D follow-up and inert in v1** — `open_dataset`'s `w_path` is unused and `w` is always None) into ONE ds (vars `u/v/ssh/…`, dims renamed `time_counter→time`, `depth*→z`). **Time-axis check**: grid_U/grid_V must share grid_T's time axis — validated by record count + exact timestamps with an all-or-none coordinate rule (a coord on one side but not the other → `ValueError`, never graft); when no file carries a decodable time coordinate, the merged "time" dim gets an integer fallback coord (so `ds['time']` always exists downstream; a plain arange reads as "no real time" → explicit `numerics.dt` required). `read_velocities` → `c_grid_to_t` → **node-layout** u/v (⇒ run needs `uv_interp: barycentric`; node+leastsq fails fast), `ssh`→eta (non-finite ssh zeroed); honours `velocity_float32`. `probe_uv_layout(ds, mode_cfg=None, mesh=None)→"node"` (pre-writer fail-fast). Var aliases (`uo/vozocrtx/…`, `vo/…`, `ssh/zos/…`) + `mode.var_*` overrides (a set-but-absent `var_u`/`var_v`/`var_eta` → `KeyError`, never a silent alias fallback). **Fail-fast guards** (each a staged follow-up, never a silent wrong answer): skewed grid (above), `mesh.rotation`→ValueError, `Fdrift3D`→NotImplementedError (open + read), `mode.sigma_layer` other than 0/null→NotImplementedError (open + read; v1 always reads the surface level, the layer was ignored silently until 2026-10-04), `em`/`m1` diffusion→NotImplementedError. **Out of scope (staged)**: **vector rotation** (grid-relative u/v → E/N; the gate for true curvilinear + global ORCA) — NEXT PR; global ORCA north-fold seam + E-W periodicity; 3D (`deptht/e3t`/partial cells/W); offline `utils` converter (same foundation); exact C-grid scheme. ## Test patterns

Tests use synthetic data built in `tmp_path` fixtures or small committed fixtures under `tests/data/` (e.g. `test_real_mesh.py`, `test_regression.py`) — no external data needed (exceptions: the `@slow` suites, and the data-gated HEALPix suites — see `KELP_TEST_DATA` in their docstrings).

- Canonical mesh: 3×3 grid (9 nodes, 8 triangles) centred at (5°, 5°) — interior node gets ~6 surrounding elements for robust interpolation.
- Constant velocity fields so displacement is analytic: `Δlon ≈ U·dt / (cos(lat)·METERS_PER_DEG_LAT)`.
- Output format 2 is pinned by `tests/test_output_format.py` (layout, CF attributes, time units per calendar, the record clock in both modes incl. backward/cycle/chain cuts, release variables, velocity NaN rule, lazy restart block, format-1 reads, concat refusals).

```bash
python -m pytest tests/          # default: 2687 collected (2652 pass, 35 data/plot skips as of 2026-10-14), 18 slow deselected
python -m pytest tests/ -m slow  # Parcels comparison + data-gated HEALPix-twin / W-sign suites
```

`@slow` tests live in four files: `test_parcels_comparison.py` (kinematic benchmarks vs v4 reference CSVs) and `test_parcels_diffusion_comparison.py` (cross-system moment comparison vs v4 reference) need a sibling Parcels repo (its benchmark outputs directory, see the test docstrings; own venv); `test_healpix_native_twin.py` and `test_w_sign_contract.py` need the HEALPix twin / native data (`KELP_TEST_DATA`, `KELP_TEST_NATIVE_DATA`). `test_parcels_diffusion_parity.py` (Parcels' two diffusion benchmarks re-run natively: Brownian moments, spatially-varying Kh skewness) is NOT slow and runs in the default suite.


**Validation suites get a mutation/honesty pass** (HEALPix Phase 5, 2026-08): after pinning measured tolerances, perturb the code or data in ~10 deliberate ways — including a UNIFORM time-axis offset, which statistics-only pins cannot see — and check that each pin fails; pin the ORDERING too (finer resolution → closer to the reference), the claim a broken remap would violate.

**Numba cache and concurrency (2026-09-12):** two processes compiling the SAME kernels into one on-disk cache (the suite plus a benchmark, a reviewer subagent, or a second worktree sharing `src/**/__pycache__`) corrupt each other's index and crash with `NRT_adapt_ndarray_to_python: 'descr' is NULL` or stale-callee results — give every concurrent process its own `NUMBA_CACHE_DIR` (under `./.tmp/`), and wipe `src/**/__pycache__` after editing a callee that is inlined across files (mesh.py → integrators.py). Same rule for campaign clones after a `git pull`.

## Fortran reference

The original Fortran tracker, its bug reports, and the comparison/benchmark
scripts are not part of this repository. The facts worth keeping:

Validation (10 particles, 10 steps, dt=3600 s, Euler): forward and backward both < 0.6 mm vs Fortran with the Fortran constant `SLM = 111300`; after the switch to 111 120 the parity test (`tests/test_regression.py::test_forward_euler_vs_fortran`) is skipped — a systematic ~11.6 m offset after 2 h at 1 m/s. Two Fortran bugs were found and fixed in the Python port: the **a11 summation bug**, and **catastrophic cancellation** in the absolute-coordinate Sarrus determinant — fixed by centering the least-squares fit on the particle (see docs/interpolation.md §1 and docs/velocity_interpolation.md §2).

| Fortran | Python |
|---------|--------|
| `SLM = 111300.0` | `METERS_PER_DEG_LAT = 111120.0` (Parcels convention; parity broken intentionally) |
| `z0 = dcos(yp*rad)*SLM` | `np.cos(yp * DEG2RAD) * METERS_PER_DEG_LAT` |
| `st_lon = xp + dt*tam_tr(i)*UU/z0` | `lon_new = lon + dt * UU / z0` |
| `elem2D_nodes(4,elem2D)` | `mesh.elem_nodes` (transposed, 0-based) |
| `nod_in_elem2D` | `mesh.node_to_elems` |
| `sFB` (+1/-1) | `mode.time_dir` (config) / `time_dir` argument |
| `tam_tr` (0/1 activation) | `state.alive_mask` |

## Conventions

1. **Numba for hot paths** — no Jax, no PyTorch. Always with a graceful Python fallback.
2. **Type hints + NumPy-style docstrings** on all public functions.
3. **Tests for every module** — synthetic data in `tmp_path`, no external files.
4. **Immutable state** — integrators return a new `ParticleState` via `.replace()`, never mutate.
5. **Reader interface** — `load_mesh` / `open_dataset` / `read_velocities` + `@register("name")`.
6. **Transient files go to `./.tmp/`** (gitignored) — never to system temp directories.
