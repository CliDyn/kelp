## core/geometry.py
- Constants: `METERS_PER_DEG_LAT = 111120.0` (= 1852×60, Parcels' nautical-mile convention — **intentionally differs** from Fortran's `SLM = 111300`), `R_EARTH = 6_400_000.0` (legacy Fortran), `R_EARTH_STANDARD = 6_371_000.0`, `DEG2RAD`, `RAD2DEG`.
- `wrap_lon → [-180, 180)`, `clamp_lat → [-90, 90]`, `metric_z0(lat)` = metres per degree longitude, `angular_rates(u, v, lat)`, `delta_lon(lon, ref)` (dateline-safe), `lonlat_to_xyz` / `xyz_to_lonlat` (unit sphere), `great_circle_distance` (spherical law of cosines on the unit sphere, radius defaults to `R_EARTH_STANDARD` — **not** Vincenty).

## core/mesh.py
- `Mesh` fields: `nodes_lon/lat (N,)`, `depth (N,)` **positive-down metres**, `elem_nodes (E, max_verts)` int32 **0-based, -1 padded** (FESOM-C max_verts=4, tri last node repeats first or -1; FESOM2 max_verts=3), `elem_center_lon/lat (E,)`, `node_to_elems (N, max_conn)` + `node_to_elems_count (N,)`, `sigma (K,)` — vertical interfaces (physical z-levels for z-level meshes, sigma values for sigma meshes; empty for 2D), `vertical_coord: "zlevel" | "sigma"` — selects the vertical geometry backend, `rotation_angles: Optional[(α,β,γ)]` — Euler frame the coords live in (`None` = geographic; set by the reader from `mesh.rotation`), `_vec_rot_factors: Optional[dict]` — per-carrier `(cos, sin)` tangent-plane factors keyed `"node"`/`"element"`, filled eagerly at load when rotated (needs geographic carrier coords), `_node_xyz: Optional[(N, 3)]` — unit-sphere Cartesian node table for the nearest scans, filled by `build_grid_hash` (see the `build_search` bullet).
- `Mesh._uv_depth_points: Optional[dict]` (2026-10, `compare=False`) — the depth-linear u/v data-point tables, filled lazily by `numerics.vertical_uv.depth_points` (never by a reader): `{placement: entry}` with STRONG references to the `sigma`, `depth` and `metadata["uv_data_last"]` objects each table was built from; valid by identity, so replacing any of them (a `max_levels` cut) rebuilds; the dict is replaced, never mutated, so a shallow copy of the mesh (which shares it) never sees the other's rebuild. `Mesh.metadata` itself IS shared by shallow copies (the run token `kelp_mesh_token`, `sigma_full`, a reader's `uv_data_last` — [tracking.md](tracking.md), [readers.md](readers.md)).
- `build_search(mesh)` — builds the **grid hash** (`build_grid_hash`, Numba-compatible, preferred); the scipy KD-tree is built **lazily** on first fallback access (`_ensure_kdtree`) — saves seconds on 11M+ node meshes. **Auto cell-size trap (2026-08)**: the auto cell `max(0.05°, sqrt(area/N)·2)` assumes a QUASI-UNIFORM mesh; on a structure-resolving mesh (1.4 m → 1.4 km in one domain) the 0.05° floor leaves 10⁴–10⁵ nodes in a cell and the in-kernel 3×3 nearest scan goes linear (~ms/particle/step, ~100× run time). `build_grid_hash` now detects it (`GRID_HASH_WARN_OCCUPANCY`, free from `counts`) and warns with a suggested cell; the escape hatch is `mesh.grid_hash_cell_size` → `set_grid_hash_cell(mesh, cell)`, which PINS the value in `mesh.metadata["grid_hash_cell"]` so any later rebuild (e.g. `particles_gen._filter_to_mesh` → `build_search`) keeps it. **The mild version needs no extreme mesh** (2026-09-12): on CORE2 the auto cell (mesh-wide mean spacing) leaves 100–135 nodes per window at the refined Arctic — no warning, 25–45 % of the tracking phase. But a smaller cell is exact only where the local spacing in mesh-frame degrees (× 1/cos(lat) in a rotated frame) is below the cell: a NON-EMPTY window can still miss the true nearest → approximate anchor → different W stencil → divergence (Beaufort at 0.5°: 2.7 % of element centres approximate, 0.16 % statuses changed in 91 d). `utils/check_grid_hash_cell.py config.yaml` (seeds + element centres: window occupancy, empty windows, approximate anchors; recommends the smallest EXACT cell) was the pre-launch check both run skills required — **since 2026-09-22 every run measures and chooses the cell itself** (`MeshConfig.grid_hash_cell_rule`, config section above); the utility remains for explicit candidates and seed positions. **Since 2026-09-12 the guard exists: `mesh.exact_nearest: true` (see config bullet) — a driver calling `load_mesh` directly must also call `set_exact_nearest`.** NB `set_grid_hash_cell` is applied by `run_tracking` and `kelp info` only — a driver that calls `load_mesh` directly must apply it itself. An explicit `cell_size=` argument still wins over the pin. Smaller cell ⇒ approximate in-kernel anchor where spacing > cell (stencil perturbation, not failure) — validation recipe in `.claude/skills/kelp-experiment/references/grid-hash-cell.md`. With `mesh.exact_nearest: false` (under the default guard the batch kernel runs the exact in-kernel search and the KD-tree is reached only on an empty mesh), `find_nearest_nodes` falls back to the KD-tree for **grid-hash misses** (empty 3×3 window → `-1`, which would wrap Python-style into `node_to_elems[-1]` downstream): never fires on quasi-uniform FESOM meshes in-domain (byte-identical there), does on HEALPix polar rings / far off-domain queries. The SINGLE-particle kernel `_grid_hash_nearest_widened` (fused/RK-stage callers, no KD available) instead **ring-widens on an empty window** (2026-08: outward Chebyshev rings, one extra ring after the first hit; APPROXIMATE anchor near poles, strictly better than a dead stage; fires only where −1 was returned — seam-gap probes no longer kill stages). The BATCH kernel deliberately calls the 3×3-only core `_grid_hash_nearest_3x3` and keeps −1 so the vectorized KD-heal stays EXACT (review-caught blocker: the widened single must never shadow that fallback). `grid_hash_dense_for_elements(mesh)` — lazy per-mesh **density certificate** (every element-bbox cell has a nonempty 3×3 window ⇒ the widened single-particle anchor is bit-identical to the batch path for every containable query); consumed by the fused bary-tinterp gate only with `mesh.exact_nearest: false` (`_bary_fused_anchor_exact` returns True under the guard without evaluating it); invalidated by `build_grid_hash`; bbox raster is over-conservative (may deny, never wrongly grants). **Node coordinate table (2026-09-22):** `build_grid_hash` fills `mesh._node_xyz` `(N, 3)` unit-sphere xyz through `_node_xyz_fill` (a Numba kernel with the scans' verbatim scalar expressions, from the RAW `nodes_lon`, never the branch-folded index longitude); every nearest kernel takes `node_xyz` directly after `nodes_lat` (the three `_gh_scan_*` helpers take it INSTEAD of lon/lat) and every launch site fetches it through `_require_node_xyz(mesh)` (clear error instead of a Numba typing error when the field is None). **Bit-identity precondition**: fill loop and scans compiled to the same math — never numpy/`math` trig (their cos/sin round differently in ~0.1–0.25 % of values: LLVM fuses a sin/cos pair in one basic block into one `sincos`; one ulp flips a near-tie anchor), each cos/sin pair of the fill in one basic block, no vector math library (`numba.config.USING_SVML` False — SVML would vectorise the fill loop but not the gather/argmin scans); `build_grid_hash` verifies it on ~4096 sampled nodes with a scan-shaped loop (`_node_xyz_selfcheck`) and warns naming `NUMBA_DISABLE_INTEL_SVML=1`. No-Numba fallback: numpy fill (KD-tree convention), no bit-identity contract. `tests/test_node_xyz.py` pins bit-identity kernel by kernel against frozen copies of the old kernels AND their helpers (`tests/_ref_nearest_kernels.py`, generated by `tests/_gen_ref_nearest_kernels.py` from `v0.9.0`, whose mesh.py equals the branch point; nothing in it imports the live mesh.py) on 11 geometries incl. edge-midpoint ties (true two-node ties: an ulp-wrong table flips some), and checks the wiring by AST (every def with `gh_node_ids`/`gh_far_rows` and every kernel launch — named, `fused_kernel(...)` or `*_mesh_gh_args(mesh)` — must carry the table); 6.3× on the scan (CORE2 auto cell: 3.2 → 0.5 µs/query at 1 thread), before/after rows in `benchmarks/nearest_scan_table.md`. Memory 24 B/node PER PROCESS (shards multiply it). Deliberately NOT done (review 2026-09-22, candidates for later): dropping the now-unread `nodes_lon, nodes_lat` from `_grid_hash_nearest_3x3/_widened` (uniform signature rule kept), building the KD-tree from the table (changes tie order on the heal path), bundling `node_xyz` into `_mesh_gh_args`.
- `find_nearest_nodes`, `find_containing_elements` (bbox prefilter → containment test only; returns `(elem_ids, in_domain)`, no weights). Containment TEST = fan triangulation (unchanged, exact for convex cells); WEIGHTS = `_polygon_weights` dispatcher: tris → the untouched `_barycentric_weights_tri` (bit-identical, incl. its degenerate sentinel), quads → `_wachspress_weights_quad` **product form** (`w_i ∝ C_i·A_{i+1}·A_{i+2}` — division-free, exact on edges/vertices, winding-invariant by odd sign powers; NO guards, NO fan fallback — convex quads are a mesh contract, reviewer 2026-07; `_fan_weights` deleted). Callers guarantee nv ∈ {3,4}. The contract is enforced at LOAD: `find_nonconvex_quads`/`validate_quad_convexity` (vectorized O(E), seam-safe, winding-agnostic; tri encodings skipped) — called by the FESOM-C reader and `build_structured_mesh`, raising with the offending ids. Full formulas: docs/interpolation.md §7.
- `build_node_to_elems(n_nodes, elem_nodes)` — **argument order trap**: `n_nodes` first.
- `Mesh.r_earth: float = R_EARTH_STANDARD` — Earth radius (m) for mesh-derived areas; set per-family by the reader (FESOM2 `6_367_500`, FESOM-C `6_400_000`). Lazy `_node_areas` field stores FESOM-C node control-volume areas when the NetCDF carries them (read for future use; nothing consumes them yet).
- `build_elem_areas(mesh)` — lazy `(E,)` float64 area cache (`mesh._elem_areas`). **File areas by default, spherical fallback**: the reader pre-fills `_elem_areas` from a FESOM2 mesh-diag `elem_area` / FESOM-C NetCDF area var (the normal case — FESOM2 diag always carries it), returned untouched (bit-parity, pole-correct), and the loader prints the area source at mesh load. Own fallback (area-less sources, e.g. ASCII) = **spherical excess × `mesh.r_earth²`** (sum of fan-triangle excesses on the unit sphere; pole-safe + frame-invariant — replaces the old planar `cos(lat)` shoelace that collapsed polar caps; pad/repeat-vertex safe via map-to-first-vertex → zero-excess degenerate fan triangle). Consumed only as ratios by the barycentric element→node u/v projection, so the radius cancels there.
- `build_boundary_info(mesh)` — lazy/idempotent coastal-element flags (`mesh._elem_is_coastal`): edge owned by exactly one element = boundary; compacted-ring edge extraction (FESOM-C -1 pad / repeated-vertex safe — the closing edge MUST be emitted, a padded-slot roll drops it); island holes = interior boundary loops, no special case; deliberately not @njit (one-time ~4 s per 1M elements (4.2 s measured on 1.00 M triangles, 2026-10-04)).
- `build_elem_neighbors(mesh)` — lazy `(E, max_verts)` int32 adjacency (`mesh._elem_neighbors`): slot k = element across edge `(verts[k], verts[k+1])` of the COMPACTED ring (same compaction as the interp kernels), -1 = boundary/unused slot; non-manifold edge (shared by >2 elements) → ValueError. FESOM's `elem_neighbors` reconstructed from connectivity; consumed by `edge_leastsq` u/v interpolation and edge-walk tracking. Python loop, ~2.5 s per 1M elements (2.5 s measured on 1.00 M triangles, 2026-10-04) (pre-warmed by run_tracking when edge_leastsq or walk) — budget minutes + transient GBs on the 23M-element global mesh.
- `_walk_containing_element` / `find_containing_elements_walk` — edge-walk containment (`elem_search: walk`): per element, winding-corrected signed-area coordinates in the `_project_to_local_xy` plane; all `≥ -1e-6` normalized (the `_BARY_EPS` tolerance class) → contained, else cross the MOST NEGATIVE edge via `elem_neighbors`. EVERY non-contained outcome (boundary edge, cap `WALK_MAX_STEPS=256`, 2-cycle projection noise, degenerate cell, invalid start) → `(-1, False)` and the batch wrapper falls back to the global machinery; near-edge accepts (margin < `_WALK_VERIFY_BAND=1e-2` normalized) are re-verified with the exact `_element_contains` predicate (the raw signed-area accept admits a ~1e-6 OUTSIDE band the local bbox prefilter rejects at boundary edges — life/death divergence, review-caught) → verdicts identical to `local` wherever the 1/2-ring scan is exhaustive = all realistic meshes (up to on-edge ties; on extreme-jitter triangulations the walk is strictly MORE complete — finds beyond-2-ring elements local falsely rejects). Measured 35 ns/particle vs 126 for the local scan (28k-tri mesh, 200k particles, 8 threads).
