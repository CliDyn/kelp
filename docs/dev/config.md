# Developer notes — configuration (`core/config.py`)

> **Covers:** `core/config.py` — the YAML → `AppConfig` loader, the config dataclasses and their load-time checks, and the engine behaviour behind several keys: the automatic grid-hash cell (`MeshConfig.grid_hash_cell_rule`) and the exact nearest-node guard (`MeshConfig.exact_nearest`), which carry most of the internals of the nearest-node search in `core/mesh.py` and of the fused kernels; the node-shared snapshot cache (`NumericsConfig.shared_fields_dir`, the only notes on `core/shared_fields.py`); beaching, periodic windows, rotation, the time window; `DiffusionConfig`.
> **Does not cover:** the user-facing option reference ([../configuration.md](../configuration.md)); the mesh search code and its other caches ([mesh.md](mesh.md)); the integrators ([integrators.md](integrators.md)); the diffusion kernels ([numerics.md](numerics.md)).
> **Code:** `src/kelp/core/config.py:load_config`, `src/kelp/core/config.py:AppConfig`, `src/kelp/core/config.py:MeshConfig`, `src/kelp/core/config.py:DiffusionConfig` (authoritative implementation).
> **Verified at:** see `docs/doc_map.yaml` (stamped via check_doc_sync --bless).

## core/config.py
- `load_config(path) → AppConfig`; sections `mode`/`numerics`/`mesh`/`data`/`time` → dataclasses. Unknown YAML keys silently ignored; an empty section (`mode:` = YAML null) loads with defaults. Load-time checks (2026-10-04) also cover `mode.time_dir ∈ {1, -1}` (stored float), `sigma_layer` + `sigma_mean` together (refused), `numerics.integrator` (`_VALID_INTEGRATORS` == `integrators.INTEGRATORS`, pinned) and `w_interp` (`_VALID_W_INTERP` == `vertical._W_METHOD_MAP`, pinned), `data.time_averaging`, quoted strings where a list is expected (`periodic_*`, `crop_bbox`), and empty `numerics.diffusion:`/`beaching:` blocks (→ defaults).
- `NumericsConfig.dt: Optional[float] = None` — auto-detected from the file time coordinate when omitted.
- `NumericsConfig.w_interp = "leastsq"` — `"nearest" | "leastsq" | "barycentric" | "idw"`. Fused 3D Euler supports nearest/leastsq only; others use the unfused path.
- `NumericsConfig.diffusion: DiffusionConfig` — see below.
- `ModeConfig.max_levels: Optional[int]` — in 3D: number of vertical interfaces kept from the surface down.
- `ModeConfig.w_positive = "auto"` — `auto|up|down`, the sign convention of the vertical velocity IN THE FILE (validated, lower-cased). Internal `VelocityField.w` is always positive-down; readers convert via `readers.resolve_w_sign` (`auto` → CF `positive` attr → CF `standard_name` upward_/downward_ → reader default: fesom2/fesomc/healpix `up`; `utils/reconstruct_w.py` output stamps `positive="down"`).
- `ModeConfig.sample_vars: list[str]` (default `[]`) — dataset variables sampled along trajectories; a single YAML string is coerced to a list, `null` → `[]`. Empty = sampling fully dormant (byte-identical output).
- `NumericsConfig.sample_interp = "leastsq"` — `"nearest" | "leastsq" | "barycentric" | "idw"`, validated at load.
- `NumericsConfig.uv_interp = "leastsq"` — `"leastsq" | "barycentric" | "edge_leastsq"`, validated at load; non-leastsq = unfused integrator paths, EXCEPT node-layout barycentric with `vel_next` (fused bary-tinterp kernels; certificate-gated only with `mesh.exact_nearest: false` — see integrators section). `edge_leastsq` = FESOM-style fit over containing element + edge neighbors (element layout only, like leastsq).
- `NumericsConfig.edge_leastsq_bc = "freeslip"` — `"freeslip" | "noslip"`: boundary-ghost value for `edge_leastsq` (mirror of centroid across the boundary edge carries the mirror IMAGE of u_own — tangential kept, normal reversed — / `−u_own`; the old freeslip copied `+u_own`, a zero-gradient ghost that let flow cross the coast, fixed 2026-09-23); inert for other uv_interp methods.
- `NumericsConfig.elem_search = "local"` — `"local" | "walk"`: containing-element search. `walk` = search once at release, then cross edges (docs/localization.md §7); verdict-identical to local (fallback chain), unfused paths only (walk+leastsq warns once).
- `MeshConfig.r_earth: Optional[float] = None` — Earth radius (m) for mesh-derived areas/metrics; validated `> 0` when set. `None` → reader family default (FESOM2 `6_367_500`, FESOM-C `6_400_000`); set explicitly only to match a model build with a non-default radius. Flows into `Mesh.r_earth`: the spherical-excess area fallback and the local projection of the barycentric cores and fused barycentric kernels use it (value-neutral there: it cancels in the weight ratios).
- `MeshConfig.grid_hash_cell_size: Optional[float] = None` — nearest-node grid-hash cell in degrees; validated finite in `(0, 45)` when set (string/number coerced to float, bool refused; `set_grid_hash_cell` applies the same bound — a 60° pin used to pass and break the next rebuild, 2026-10-04). `None` → the automatic rule below. Applied reader-agnostically by `run_tracking` right after `load_mesh` via `core.mesh.set_grid_hash_cell` (pins `mesh.metadata["grid_hash_cell"]` + rebuilds). See the `build_search` bullet for when it matters.
- `MeshConfig.grid_hash_cell_rule: str = "occupancy"` (`"occupancy" | "legacy"`, validated lower-cased; inert when `grid_hash_cell_size` is set) — **2026-09-22**: the automatic cell is CHOSEN BY MEASUREMENT, not by the mesh-wide mean spacing. `run_tracking`, `track_particles(grid_hash_cell_rule=)` and `kelp info` call `core.mesh.apply_grid_hash_cell_rule(mesh, rule)` AFTER `set_exact_nearest` (the mode depends on the flag), in the else-branch of the explicit-cell path (an explicit `grid_hash_cell_size` is pinned instead and reported `explicit`); `load_mesh`/`build_search` still build the LEGACY cell (library users and the synthetic test meshes keep it — a direct driver applies the rule itself). `choose_grid_hash_cell(mesh, *, exact=None, sample=200_000, seed=0, min_median=8, approx_tol=0.005, max_far_rows=64, steps=12, min_gain=2.75, max_unprovable=0.20, max_hash_mb=128.0)`: ≤ 200k sampled element centres (deterministic; non-finite centres dropped; Numba required — without it the reader's cell is kept), their exact nearest node ONCE through `_grid_hash_nearest_batch(..., exact=True)` (cell-independent θ/cap extent), then per candidate `legacy/√2^k` without rebuilding the hash: node counts per cell (`_gh_lon_branch`/`_gh_grid_geometry`/`_gh_cell_index` — the build's arithmetic factored out, pinned bit for bit), a 2-D prefix sum, and the prange `_gh_sample_stats` → 3×3 occupancy, the widening share (the search's OWN certificate `_anchor_provable_rect(rx=ry=1)` on the window, plus empty windows and windows without the true nearest — the uniform-coverage bound over-counted 7.4 % vs 3.8 % on CORE2, review 2026-09-22), approximate share (true nearest OUTSIDE the window — the guard-off risk), and the scan-cost proxy (provable: occupancy + 9 cells + one certificate; else the certificate's rectangle node count + the cells the growth visits `9 + rx·(2ry+1) + 2ry` (all columns: `9 + 2ry`) + one certificate per growth iteration; counting cells is what stops a cell far below the spacing from looking free). Proxy weights `_GH_COST_CELL = 1`, `_GH_COST_CERT = 20` (one certificate evaluation per growth iteration, `max(rx, ry) + 1`; calibrated against the measured exact batch search per candidate cell on CORE2 and the 80–88 °N structured mesh — without it the argmin sat one ladder step below the measured optimum). Mode `exact` → argmin mean cost (ties → larger cell) over the ELIGIBLE candidates — widening share ≤ `max_unprovable` (20 %) and hash offsets ≤ `max_hash_mb` (128 MB = 32 M cells; the legacy row is always eligible) — taken only if it predicts ≥ `min_gain` (2.75×), else legacy; `approx` (guard off) → smallest cell with empty == 0, median ≥ 8, approx ≤ legacy + tol, hash ≤ `max_hash_mb`, else legacy. The eligibility bounds are the proxy's validity domain (review 2026-09-22: on the 11.5 M-node global mesh the argmin was the cap-limited LAST candidate, 46 M cells = 185 MB of offsets per process, 21 % widening, predicted 5.9× where 1.4–3.1× was measured; bounded, the rule takes 0.0513° = 92 MB, predicted 4.9×, measured 1.7–2.6×). Hard limits `_gh_far_rows_for ≤ 64`, `nx·ny ≤ _GRID_HASH_MAX_CELLS`; per candidate the transient is `counts` (int64) + an int32 in-place prefix sum (no axis-0 temporary). `apply_grid_hash_cell_rule` pins a different choice via `set_grid_hash_cell` (which itself stamps `grid_hash_cell_rule = explicit`), stores `mesh._gh_report`, stamps `metadata["grid_hash_cell_rule"]` + `grid_hash_cell_mode` (exact/approx); `build_grid_hash` drops a report that describes another cell. Reused mesh: an explicit pin is never overridden (reported `explicit`); the same rule+mode returns the earlier report (no second ladder for a `track_particles` loop); a different rule or mode after an earlier `occupancy` pops that pin, rebuilds the reader's cell and decides afresh (`legacy` after `occupancy` restores the reader's cell; the strict guarantees never inherit an exact-mode cell). `describe_grid_hash(mesh)` = the one-line report (run verbose + `kelp info`). Writer metadata ALWAYS: `grid_hash_cell` (resolved, float) + `grid_hash_cell_rule` (occupancy/legacy/explicit) — an old run is repeated by pinning that value or `legacy`. NOT byte-identical to legacy at exact ties (scan order breaks them) and for guard-off anchors; the synthetic run_tracking fixtures ARE identical (pinned). Exact mode deviates from legacy only for a predicted gain ≥ `min_gain` = 2.75×, the mid-gap between the two calibrated classes (`benchmarks/grid_hash_cell_rule_table.md`, 2026-09-22): QUASI-UNIFORM meshes predict 2.0–2.2× (HEALPix CORE2 twins z6/z7/z8 2.03–2.06, CORE2 2.16) — a smaller cell buys ~1.6× on the search in isolation, nothing measurable on the step of a global release (CORE2, 60 daily steps × 200k: 93–97 ms at the legacy cell vs a mean of 97 ms at half of it) and measurably costs at high latitude (HEALPix 80–88 °N +17–24 %, land-cap seeds ×3.5) — so they KEEP the reader's cell; STRUCTURE-RESOLVING meshes predict ≥ 3.6× (FESOM-C `sns_multi_m8` 3.6 → 0.058° → 0.014°, window 207 → 13, search 1.7×; the 11.5 M-node global mesh 4.9 → 0.145° → 0.051°, search 1.7–2.6×; the synthetic estuary (ratio 100) 0.05° → 0.0016°, strip cost ÷ 30, ×26 measured). The proxy's own error is up to ~2× across meshes and hardware (measured/proxy 0.45–1.85 ‰), hence the margin. A release confined to a refined region still wants the explicit cell (CORE2 Arctic at 0.5°: −28 % per step on the Beaufort run; the rule samples the mesh, so it predicts CORE2's global 2.15–2.16 and keeps 1.38°). The sample is the MESH, not the seeds (a coarse-region release may prefer an explicit cell; `utils/check_grid_hash_cell.py` probes seeds and prints the rule's line too).
- `MeshConfig.exact_nearest: bool = True` (guard added 2026-09-12, default ON since 2026-09-14; `false` + `grid_hash_cell_rule: legacy` = pre-guard anchors bit for bit — since 2026-09-22 the default rule may change the cell in strict mode too) — exact nearest-node anchor guard: `run_tracking` → `core.mesh.set_exact_nearest(mesh, True)` (`mesh.metadata["exact_nearest"]`, survives hash rebuilds); `find_nearest_nodes` then runs the batch kernel in exact mode (`_grid_hash_nearest_batch(..., exact=True)` → the in-kernel exact search `_grid_hash_nearest_exact` per query; the KD heal is reached only on an empty mesh). Provability (`_anchor_provable`, geometry-aware after review round 1): the cap of angular radius θ around the query (θ in lat, asin(sin θ / cos lat) in lon, unbounded at a pole) must fit inside the intervals the window ACTUALLY searched — a wrap grid's seam cell is narrower than `cell` (360 % cell), clipped rows/columns reach the grid edge (no nodes beyond), and on a non-wrap grid the ±360° images of the cap must miss the node range (near-global mesh on one branch); `_cap_extents` gives (θ, lon extent) and `_nearest_provably_exact` is the uniform-coverage core (kept for its unit tests; no kernel calls it); the certificate centres on the SAME cell as the search (`_gh_fold_dlon`, the one fold rule shared with `_gh_cell_of` — review round 2). **Every fused kernel is exact under the guard (2026-09-12 follow-up):** the 2-D kernels (leastsq steady/tinterp/PCHIP × Euler/RK2/RK4, the Euler pair kernel, node-layout bary RK2/RK4 tinterp) and the fused 3-D Euler kernel anchor each evaluation SITE (start, RK stages, final) through `_fused_site_anchor(…, exact)`: guard off → the historical `_grid_hash_nearest_widened` (byte-identical); guard on → `core.mesh._grid_hash_nearest_exact` = the 3×3 hit iff `_anchor_provable` (exactly the batch path's decision), else a RECTANGLE widened by the deficits of `_anchor_provable_rect` (bitmask 1 rows / 2 columns / 4 every column — pole cap or ±360 image on a non-wrap grid; rows and columns grow independently, so a polar query scans only the polar rows, never the whole grid) until the best node is provably nearest; the batch path under the guard calls the SAME function (`_grid_hash_nearest_batch(..., exact=True)`; the KD heal broke exact ties in a different order — review round 2) ⇒ fused == unfused bit for bit incl. ties; row segments scanned as contiguous CSR slices (`_gh_scan_row_range`/`_gh_scan_row_window`: a polar row on a fine cell = thousands of empty cells, few nodes); an empty 3×3 grows as a square until the first hit (full rows only in the polar cap); BUDGET `mesh._gh_far_rows` = longest element edge in cells + 2 (`_gh_far_rows_for` in `build_grid_hash` from the CACHED `mesh._gh_max_edge_deg` (`_gh_max_edge_for`, chunked, incl. the closing edge of padded triangles); floor 4, cap 4096 with a RuntimeWarning; threaded as the `gh_far_rows` kernel arg / `far_rows`): a query whose nearest node is farther than the budget (lat terms; judged by the clearance of the scanned rectangle, the clamped edge window's θ, or a latitude offset) is outside every element ⇒ the best node seen or the widened anchor, no grid scan (a 400 k far-outside-seed step cost a minute with a whole-grid scan; such particles die this step). A FIXED 16-row budget broke exactness on a multi-resolution mesh whose coarse elements span 50 cells of the fine patch's cell (review round 3: 26 % false OUTSIDE) — hence mesh-derived. Empty window: a growing square until the first hit, except in the polar cap (`_GH_EXACT_SHORT_ROW_CELLS`: rows angularly ≤ 32 cells) → full rows; the far exit is a geometric CLEARANCE (rows: the band's latitude offset; columns: the longitude offset at the band's poleward edge, capped by the across-the-cut offset on a non-wrap grid) ≥ budget, evaluated only while nothing within the budget was seen. Cost of a far-from-node seed (land, off-mesh) ∝ (budget/cell)² cells ONCE at seed load / step 1 — CORE2 auto cell: cheaper than main's KD heal; a mesh whose longest edge is hundreds of cells (Delaunay hull slivers, absurdly small cells) pays ~1 ms per such seed. Beyond the budget the anchor is 'best seen', not the KD nearest of main — dead-on-arrival deep-land seeds may get a different BEACHED/OUTSIDE remap under `beaching.on_failure`. NUMBA CACHE HAZARD: `_grid_hash_nearest_exact` is inlined into ~50 kernels of integrators.py via `_fused_site_anchor`; numba invalidates on the CALLER file's mtime only, so a change to the search alone leaves stale fused kernels on disk — wipe `src/**/__pycache__` after editing mesh.py. Pinned vs brute force on random geometries, seam cell, padded near-global grid, poles, far queries, a multi-resolution mesh. No runner round trip: the flag/heal handshake and the density-certificate gate are NOT used for these kernels (the gates return True under the guard); the fused 3-D RK2 bary kernels anchor their stage sites through the same exact search under the guard (round 4: their flag/heal rounds were slower than unfused too) and keep the 2026-08 flag/`_run_fused_3d_with_heal` handshake only for the guard-off empty-window case. A first version of this follow-up used the flag/heal rounds for the 2-D kernels too — the review measured it SLOWER than the unfused path where half the anchors are unprovable (80–88 °N, auto cell: one round per site, ~3× the kernel work), hence the in-kernel search. The fused 3-D Euler kernel computes W BEFORE the u/v verdict (vel_w of a particle dying by interpolation failure now matches the unfused path; guard-independent). `_rk4_step_unfused` and the split diffusion kick wrap/clamp only the MOVED/kicked entries (a frozen particle at lon 180.0 came back at −180.0, others could be rounded once by the wrap; same rule as `_apply_displacement`; guard-independent, affects dead/NOT_RELEASED positions only). `rk45` (`_rk45_eval`) anchors every adaptive substep through `_fused_site_anchor(…, exact, far_rows)` too — no rejection any more. `run_tracking` ALWAYS calls `set_exact_nearest(mesh, bool(config.mesh.exact_nearest))` (False clears a stale flag). `false` (with `grid_hash_cell_rule: legacy` or the old run's pinned cell) = byte-identical to the pre-guard engine; metadata attr `exact_nearest` always stamped (0/1). Cost when on: `benchmarks/nearest_scan_table.md` §2 (`benchmarks/exact_nearest_cost.py`, 400 k particles, 8 thr, re-measured 2026-09-22 with the node coordinate table, which supersedes the 2026-09-12 set): about 0 % on a global HEALPix release and the fused 3-D RK2 kernel, +7–20 % for seeds that die (far outside, inside a land cap), +15 % HEALPix 80–88 °N, +37 % structured mid-latitude, ×2 at 80–88 °N with the automatic cell, +61 % in the 89–90 °N band, ×4.6 with a cell 3× below the spacing; the fused path stays 1.04–3.6× faster than the unfused path under the guard (the first flag/heal-rounds version was measured SLOWER than unfused at 80–88 °N: one runner round per site).
- `MeshConfig.rotation: None | "fesom2" | [α,β,γ]` — coordinate-frame Euler angles (deg) for pole-safe tracking, FESOM2 + HEALPix (fesomc/nemo reject). `None` (default) → geographic, byte-identical; `"fesom2"` → (50,15,−90); validated in `__post_init__` (3-list coerced to floats). Resolved by `readers.fesom2._resolve_rotation_angles` (FESOM2) or inline in `healpix._apply_rotation` (HEALPix), stored as `Mesh.rotation_angles`.

### DiffusionConfig
`enabled=False` (default) → byte-identical behaviour to no-diffusion.
- `scheme: "uniform" | "em" | "m1"` — uniform takes scalar Kh from config; em/m1 read spatial Kh fields from the dataset.
- `composition: "split" | "combined" | "split_rk"` — auto-resolved by the tracking layer (uniform → split; em/m1+Euler → combined; em/m1+RK2/RK4 → user must opt in with `"split_rk"`, one-time RuntimeWarning).
- `kh_zonal`, `kh_meridional: float` — m²/s, uniform only.
- `var_kh_zonal`, `var_kh_meridional: Optional[str] = None` — dataset variable names for em/m1; reader-side defaults `Kh_zonal`/`Kh_meridional`, layout auto-detected from dim names.
- `dres_m: Optional[float]` — central-diff offset (m) for Kh gradients; None → mesh-derived default (median element edge, clipped to [100 m, 50 km]).
- `seed: int` — counter-RNG seed, validated to `[0, 2**64)`.
- `kh_eval_position: "end"` — split-RK only: sample Kh at `"start"` of step or `"end"` (post-RK).
