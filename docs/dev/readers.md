## readers/
Registry in `__init__.py`: `get_reader(name)` auto-imports known modules. Shared helpers: `_detect_engine(path)` (`"zarr"` for `.zarr` paths or dirs with `.zattrs` (v2) or `zarr.json` (v3, since 2026-10-04), else `"netcdf4"`), `extract_time_info(ds) → (times_sec, file_dt)` (datetime64 / cftime / numeric-with-units; `(None, None)` if uninterpretable), `time_axis_epoch(ds) → ("seconds since YYYY-MM-DD hh:mm:ss[.f]", calendar) | None` (same origin and decoding branches; None for a bare unit, an index axis, NaT, or an axis xarray cannot decode — the output then gets `units = "seconds"` + `NO_EPOCH_NOTE` as `time_origin`), `_read_kh_fields` (spatial Kh for em/m1, layout auto-detected). Shared with `tracking.py` and `kelp info` (2026-10, moved from `tracking.py` so that `kelp info` does not import the tracking loop and its integrators; `tracking` imports them under the same names): `_prepare_dataset(reader, mesh, ds)` (the optional `prepare` hook, below), `_time_option_kwargs(config)` (the `data.time_stamp`/`time_window`/`time_offset` keys as `open_dataset` kwargs: only for the mesh types in `_READER_RESOLVES_TIME` = `("fesom14",)`, a `TypeError` naming every key set for any other type; `ValueError` for `data.time_averaging` set with such a type), `_dry_mask_kwargs(config)` (`{"dry_mask_var": beaching.dry_mask_var}` as an `open_dataset` kwarg only for the mesh types in `_READER_OPENS_CONSUMED` = `("fesom14",)`, with beaching enabled and the key set; empty otherwise, so other readers' calls are unchanged), `_describe_record_times(ds, offset)` (the `record times` summary line from `ds.attrs["fesom14_time_source"]`; None for other datasets), `RESOLVED_BY_READER` (`"resolved_by_reader"`, the output's `time_averaging` for those types).

Reader interface (all `@staticmethod`, register with `@register("name")`):
```python
load_mesh(mesh_cfg[, mode_cfg=None]) → Mesh       # mesh_cfg.meshpath; mode_cfg passed only when the signature takes it (healpix)
open_dataset(path, v_path=None, w_path=None, mode_cfg=None, **extra) → xr.Dataset
                                                 # run_tracking ALWAYS passes mode_cfg=; extra: diffusion= (fesom2, active Az), eta_path= (healpix, data.ncinput_eta set),
                                                 # time_stamp= / time_window= / time_offset= (fesom14, each only when its data.* key is set),
                                                 # dry_mask_var= (fesom14, beaching enabled and beaching.dry_mask_var set)
read_velocities(ds, timestep, mesh, mode_cfg=None, diffusion=None, sample_vars=None, velocity_float32=False) → VelocityField
read_scalar_fields(ds, timestep, mesh, varnames, mode_cfg=None) → dict[str, ndarray]  # optional; node-based, trimmed to mesh.sigma
probe_uv_layout(ds, mode_cfg, mesh) → "node" | "element"   # optional; metadata-only, the pre-writer fail-fast
prepare(mesh, ds) → None                         # optional (2026-10); run at every entry (run_tracking after open_dataset, then each realization; kelp info once), readers._prepare_dataset
native_uv_vertical = "layer" | "level"           # optional class attribute (2026-10); default "layer"
```
- **Depth-linear hooks (2026-10, docs/vertical.md §2.1)**: `prepare(mesh, ds)` runs at EVERY entry — right after `open_dataset` in `run_tracking` (before the sampling probes and the writer, so its refusals leave no output file) and at the entry of each `run_single_realization`, after the `max_levels` cut, so it sees the levels in use ([tracking.md](tracking.md): 1 + R calls for R realizations, one per direct call). The engine keeps no record of what a mesh was prepared for and writes nothing into `ds.attrs` or `mesh.metadata` for it: whatever changed since the last call (the dataset, the kept levels, `mesh.depth`, a shallow copy of the mesh, the reader), the hook sees the current state. Use it for mesh-relative facts of a dataset (e.g. a data prefix to declare, which it must SET each call — another dataset or reader may have replaced it: assign a new array each call; do not keep writing into an array assigned earlier, the engine does not read it after the first table). The engine takes a SNAPSHOT of the declaration at first use: the depth-point table is built from an owned, read-only copy that replaces the reader's array in `mesh.metadata["uv_data_last"]`, so a later write into the reader's array, its base or any view of it changes nothing, and a write into the snapshot raises (a copied or unpickled mesh gets a new snapshot, validated again, on first use). A reader never un-freezes or writes into the array it finds in `mesh.metadata["uv_data_last"]` (the engine's snapshot: a write there that is frozen again keeps the old table): it computes from it and assigns a new array. It writes its facts INTO `mesh.metadata` and never replaces the dict (that would drop `sigma_full` and the engine's metadata). A failed `prepare` leaves nothing of the engine behind; the next call runs it again. It may derive facts from the dataset's full axes, `mesh.depth` and `mesh.sigma` (the kept levels). It must not REPLACE `mesh.sigma` or `mesh.depth`: both are tracked by identity (the depth-point tables; `_apply_max_levels` would take a replaced table as the new full one). Cost: one hook per entry (the FESOM 1.4 hook: 0.41 s per call on the published LR mesh, 127k nodes, 46 levels). `native_uv_vertical = "level"` declares that the reader's u/v sit on the levels (`VelocityField(uv_vertical="level")`, `K` rows): such a run is depth-linear without the option, `mode.uv_vertical: linear` is refused for it, and `run_single_realization` applies `max_levels` to the mesh itself. A 2-D read of such a reader (`Fdrift3D: false`, one level) must return a 1-D `u` marked `uv_vertical="layer"`: `VelocityField` refuses `"level"` on a 1-D `u` (the `uv_vertical` row of [core.md](core.md)). The FESOM 1.4 reader sets both (`native_uv_vertical = "level"` and a check-only `prepare`, its bullet below); the FESOM2 and HEALPix readers set neither, return `"layer"` fields and the tracking layer marks them (`tracking._mark_depth_linear`). A reader may also DECLARE the last finite point of its u/v column per node, `mesh.metadata["uv_data_last"]` (int `(N,)`, mesh-node order, `-1` = surface only, the surface value then must be finite), which caps the depth-linear table (`numerics/vertical_uv.py`).
- `read_scalar_fields`: FESOM2 `nz1`→K-1 / `nz`→K trim, 2D-mode level pick like velocities; FESOM-C sigma dims + **node-aware** 2D reduction `_reduce_scalar_to_2d` (`_reduce_to_2d` is element-hardcoded — never reuse it for node fields). Missing/element-sized vars → ValueError (fail-fast at run_tracking startup).

- **fesomc.py** 3-D W (2026-09-23, final form after the review of PR #102): tracks with FESOM-C `w` = `Wvel` (positive-UP flux through the sigma INTERFACES, 0 at surface and bottom, `fv_3D_vel.F90:vert_vel_sigma`); the reader returns `W = −Wvel` (sign via `resolve_w_sign`, default up) and nothing else; the SIGMA STEP integrates the particle's sigma fraction `s = z/H_p`, `ds/dt = W/H_p`, placing every RK stage at `z = s·H_p(x_stage, t_stage)` and the end at `s_new·H_p(x_new, t_end)` (`integrators._sigma_col_H`/`_eta_blend`/`_sigma_end_eta`/`_EtaView`, `sigma_eta_start`/`sigma_eta_end` kwargs: the tracking layer supplies the surface at the step's start and end from ONE function of time (`tracking._eta_at_time`: PCHIP where a stencil exists and PCHIP is on, else the linear payload blend; discrete mode: the next record as the end) — end of a step and start of the next are bit-identical, s continuous across steps (also across steady-fallback steps between PCHIP steps) and a resumed run reproduces the continuous one (TestSigmaRestartIdentity); a mutable carry of the previous end surface broke that (1 ulp); layers/clamp/kicks use the same `H_p` via `H_col`/`H_particle`/`sigma_col`) — exact for moving surface + sloping bottom + uniform σ̇ (TestSigmaIntegration). `vel_w` on sigma meshes = the dia-sigma flux positive down. `w_cart` REFUSED (lacks the dia-sigma part). History: w_cart as W → centred η_t in W → start-of-step depth scaling → s-integration (docs/vertical.md §3).

- **healpix.py — depth-linear u/v (2026-10)**: `load_mesh` with a 3-D `mode_cfg` (`Fdrift3D`) on the DUAL geometry reads the leading finite count of `u` down every store column at t=0 (`_finite_prefix_per_cell`, `_LEVEL_BLOCK` levels at a time, BEFORE the bathymetry choice — a `deptho` deeper than the u prefix would otherwise point the depth-linear table at a slot the reader zeroes) and declares it in mesh-node order through the same store index the data compaction uses: `mesh.metadata["uv_data_last"] = (nfin_u[mesh._healpix_data_idx] - 1).astype(int32)` (`-1` = no u in the column; never on a mesh node, land is dropped by the wet mask). - **fesom14/ — FESOM 1.4 (2026-10, `mesh.type: fesom14`; `reader.py` `Fesom14Reader`, `_ascii_mesh.py`, `_polygons.py`, `_layout.py`, `_timeaxis.py`)**: FESOM 1.4 is a P1 model — u, v, w, T and S share the 3-D nodes, which sit ON the z-levels — so the reader returns u/v/w `(K, N)` on the levels, node layout, `uv_vertical="level"` (`native_uv_vertical = "level"`): every 3-D run is depth-linear between the levels ([../vertical.md](../vertical.md) §2.1; `mode.uv_vertical: linear` is refused for it), `uv_interp: barycentric` required. **Approximation**: FESOM 1.4 itself interpolates P1 on the tetrahedra of its 3-D mesh; KELP takes the triangle's barycentric weights times each vertex's own linear profile in depth (prism-wise) — the same on the levels and along each node's column, different inside a prism. **Validation status**: the level-wise form against the published CMIP6 output (data-gated `tests/test_fesom14_published_lr.py`, `KELP_TEST_FESOM14_DATA`); the 3-D-node (raw writer) form and the ASCII mesh only against the format description of the FESOM 1.4 source and a real-geometry round trip (the published LR mesh and fields written as an ASCII mesh and raw-writer files give bit-identical trajectories) — NOT against real raw output, of which none is published.

- **structured.py** (foundation, TODO 4.6): `build_structured_mesh(lon2d, lat2d, wet_mask, …)` maps any logically-rectangular (curvilinear/regular) grid onto an unstructured **quad** `Mesh` — nodes = wet cell-centre (T) points **referenced by ≥1 fully-wet quad** (orphan wet cells with no fully-wet quad — 1-cell channel, ragged coast, diagonal-only island — are EXCLUDED: they'd be dead-end nodes → false OUTSIDE), elements = quads of 4 logically-adjacent T-points kept iff all 4 wet (land corner → quad dropped = coastline). Stashes `mesh._structured_shape=(ny,nx)` + `mesh._structured_node_id` ((ny,nx)→node id, −1 land **or orphan**). `c_grid_to_t(u_faces, v_faces, node_id)` averages Arakawa-C faces → T-points (node layout; **non-finite (NaN/`_FillValue`) faces → 0** before averaging, so a masked land face can't poison coastal wet T-points); `field_to_nodes(field2d, node_id)` compacts a T-point scalar (eta/temp). Model-agnostic — adapters feed it.
