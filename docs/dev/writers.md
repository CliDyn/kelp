## writers.py
- **Output format 2** (release 1.0; the user-facing description is `docs/io_and_time.md` §5): global `kelp_output_format = 2` (int32; `writers.OUTPUT_FORMAT`), `Conventions = "CF-1.8"`, `featureType = "trajectory"`; dims `trajectory` (fixed) + `time` (record dim, unlimited/resizable — renamed from `obs`, which stays in `_RESERVED_VAR_NAMES` with the new `release_lon/lat/z/time`); `time(time)` + `trajectory(trajectory)` coordinate variables; per-record vars `(trajectory, time)` — the record dim is the INNER one (documented CF deviation: contiguous tracks). Attrs identical on both backends: `trajectory` `cf_role = "trajectory_id"` (values `particle_offset + arange(P)` via `set_trajectory_ids`); `lon/lat/z` `standard_name`+units, `z` `standard_name = "depth"`, `positive = "down"`; `coordinates = "lat lon z"` on `status`, `failure_reason`, sampled vars, NOT on `vel_*` (start-of-step values). Fill NaN for float per-record vars (`lon/lat/z`, `vel_*`, sampled) and `release_*`; `failure_reason` fill 0. Format 1 = no `kelp_output_format`, dim `obs`; still read by `load_trajectories`, `load_restart`, `utils/concat_trajectories.py`, `visualization.TrajectoryDataset`; no converter.
- `TrajectoryWriter(path, n_particles, metadata=None)` — streaming writer; **backend chosen by extension**: `.nc` → NetCDF4 (zlib, unlimited `time` dim), `.zarr` → Zarr v3 (chunked). Same API: `.open()` (creates a NEW file, an existing one replaced, and resets the two in-memory views below), `.append(state, time_value, sampled=None)`, `.write_checkpoint(state, step_i, file_idx)` (overwritten each call), `.close()`, context manager. Three setters (both backends; buffered NetCDF flushes first and writes through `_begin_write`/`_end_write`): `set_time_units(units, calendar=None, origin_note=None, cycle_period=None)` (attrs of `time`: with a `since` epoch `standard_name`/`axis`/`calendar`; without one `units = "seconds"` + `time_origin = readers.NO_EPOCH_NOTE`, no `standard_name`; `forcing_cycle_period` + `comment` under cycle; a writer never given it writes `units = "seconds"`), `write_release(lon, lat, z, time)` (four `(P,)` arrays, GEOGRAPHIC lon/lat; `release_time` gets the units/calendar of `time` only when written, so no NaN ever sits under CF units — cftime decodes a NaN to the epoch), `set_trajectory_ids(ids)`; `write_release`/`set_trajectory_ids` raise ValueError when a length ≠ `n_particles` (zarr 3.2 truncates silently). Zarr: `time` attrs set later survive block flushes (pinned).
- In-memory views of a writer (nothing is read back from or added to the file): `global_attr(name, default=None)` — the global attributes written through it (construction `metadata` + `set_global_attr`); `bound_rule(name, default=None)` / `bind_rule(name, value)` — run-wide rules bound by the segments that use it (first binding kept; `run_single_realization` binds `mode.uv_vertical` before its first write and refuses a later segment with another value). `open()` resets both: `global_attr` to the construction metadata, no bindings.
- Lazily creates the int8 `failure_reason` variable (CF `flag_values`/`flag_meanings`; on the Zarr backend too since 2026-10-04, set on the live `create_array` handle, as are the `status` flags) when `state.failure_reason` is set; `vel_u/vel_v` (when a record carries `u`) and `vel_w` (when a record carries `w` — never in 2-D) are created lazily and INDEPENDENTLY — except that `run_single_realization` declares them up front (`TrajectoryWriter.declare_velocity(w=Fdrift3D)`, review 2026-10-14): a segment resumed when every particle is dead records no velocity and, lazily, lacked the variables, which `concat_trajectories` refused. Once a lazy var exists, every record writes it: the provided value or its fill column (explicit in NetCDF; the format-1 NetCDF had no `_FillValue`, so an unwritten velocity record read 9.97e36).
- `append(state, t, sampled=None)` — `t` = the record label in seconds (format 2: both modes; tracking computes it, see the tracking bullets). Sampled scalars become lazy `f8 (trajectory, time)` vars with `_FillValue=NaN` (late creation NaN-backfills earlier records; Zarr: attrs must be set on the live `create_array` handle — a later `resize` drops attrs set via transient `store[name]`), plus `coordinates` and a `comment` on the sampling instant. Reserved names (`_RESERVED_VAR_NAMES` + `restart_*`) → ValueError. `TrajectoryWriter(..., sample_var_attrs=)` carries units/long_name. Checkpoints never store sampled values. `load_trajectories` discovers any extra `(trajectory, time)` or `(trajectory, obs)` var generically.
- **Restart block is LAZY + crash-safe (format 2)**: no `restart_*` variable exists until the first `write_checkpoint` (`_ensure_restart_block`, both backends) — it creates `restart_valid` FIRST and writes 0 (NetCDF: `sync`) before any payload variable, then the payload, then 1 (the clear-first/set-last order of 2026-09-23 now covers the first checkpoint too). Format 1 created the block at `open()` (9.97e36 NetCDF / 0 Zarr without a checkpoint).
- `load_restart(path) → {"state", "step_i", "file_idx", "wet_streak", "rotation_angles", "release_step", "particle_offset", "uv_vertical"}` (`uv_vertical`: the standalone file's `restart_uv_vertical` attribute, else the trajectory file's `uv_vertical` attribute, else `None` = `layer`) (state includes `failure_reason`/`release_step`/`elem`/`release_lon/lat/z` if stored; `wet_streak`/`rotation_angles`/`release_step` None when absent); raises `ValueError("No valid restart checkpoint in …")` if no valid checkpoint — a missing flag or a NetCDF flag created but never written (masked) is invalid (`np.ma.filled(flag, 0) != 1`). `write_checkpoint(state, step_i, file_idx, wet_streak=None, rotation_angles=None, release_step=None)` — lazy `restart_wet_streak`/`restart_release_step`/`restart_elem` (elem read off `state.elem` directly) int32, `restart_release_lon/lat/z` f8 (read off `state.release_*`, MESH frame) + scalar `restart_rotation_alpha/beta/gamma` attrs (only when set/rotated), both backends.
- `write_restart_file(path, state, step_i, file_idx, *, wet_streak=None, rotation_angles=None, release_step=None, particle_offset=None, uv_vertical=None)` (`uv_vertical="linear"` → attribute `restart_uv_vertical`; `None`/`"layer"` write nothing, byte-identical) — **module-level** (not a `TrajectoryWriter` method): writes a **standalone** NetCDF restart (same `restart_*` schema as `write_checkpoint`, so `load_restart` reads it identically), but as its own self-contained file rather than embedded in a trajectory output. Use it to drop **one numbered, kept restart per checkpoint** (`restart_step<NNN>.nc`) into a dedicated dir for a **resumable-chain** driver (the embedded `write_checkpoint` only ever holds the latest, overwritten each call). `release_step` falls back to `state.release_step`; stores `restart_release_lon/lat/z` from the state; raises ValueError when a per-particle array's length ≠ `len(state.lon)`. The resumable-chain pattern (segment outputs + numbered restarts + resume + concat, for compute-time-limited jobs) is the subject of docs/io_and_time.md §6.
- `load_trajectories(path) → {"lon","lat","z","status"} (P,T), "time" (T,) raw seconds, "trajectory" (P,)` plus `failure_reason` / `vel_*` / sampled vars / `release_lon/lat/z/time` (P,) when present; reads both layouts (`(trajectory, obs)` format 1, `(trajectory, time)` format 2), masked values → NaN.
- **Mid-run readability / flush cadence**: a NetCDF4 (=HDF5) file holds an exclusive write lock while open, so it is unreadable by other processes until `close()` (and a hard-killed run leaves it un-closed). `TrajectoryWriter(..., flush_every=N)` (config `numerics.output_flush_every`, CLI `--flush-every`) makes the **NetCDF** backend buffer N records (copies) then open-append-close each batch (`_NetCDF4Backend._flush` via `_begin_write`/`_end_write`; `_flush_block` is the Zarr backend's) → no lock between flushes, **byte-identical output**; `0` (default) keeps the file open + `sync()` per append. The **Zarr** backend is lock-free (chunked objects) and **block-buffers**: record columns accumulate in RAM and flush one whole obs-chunk at a time (`_flush_block` → `arr[:, start:end] = block`), and the obs-chunk width is **adaptive** (`OBS_CHUNK_MAX=256` / `TARGET_CHUNK_BYTES≈4 MB`, computed from the trajectory-BLOCK size) — the old per-step single-column write recompressed a `(n_particles, 256)` chunk (~260 MB at 127k nodes) every step (no Zarr write cache) and ran 2×+ slower than NetCDF (development measurement, not recorded in the repository); both backends' `write_checkpoint`/`close` flush the buffer first, lazy vars back-fill to the on-disk length (`_flushed`). **Trajectory-axis blocks (TODO 5.4, 2026-08)**: above `TRAJ_CHUNK_MAX=500_000` particles the trajectory axis is split into 500k blocks (`chunks=(traj_chunk, obs_chunk)`), so a particle subset reads only its blocks (~4 MB chunks instead of a 63 MB full column at 7.9M); at or below the threshold the layout is the historical single block, byte-identical. The obs flush covers all blocks in one assignment (chunk-boundary flushes write each chunk once; a mid-buffer checkpoint / final partial buffer may rewrite the trailing chunk — pre-existing). Old outputs keep their layout — the analysis skill documents both read patterns.
