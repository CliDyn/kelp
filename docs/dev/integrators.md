## numerics/integrators.py
Shared signature: `step(state, vel, mesh, dt, time_dir, layer=0, **kwargs) → ParticleState` (immutable — returns a new state via `.replace()`).

- **3D auto-detection**: `vel.w is not None and vel.u.ndim == 2` → per-particle layers + vertical displacement.
- Horizontal update: `lon += dt·UU/z0`, `lat += dt·VV/METERS_PER_DEG_LAT`; vertical: `z += W·dt`.
- Registry `INTEGRATORS = {"euler", "rk2", "rk4", "rk45"}`, `get_integrator(name)`.
- **rk45 (TODO 2.3)**: Dormand–Prince 5(4), per-particle adaptive substepping INSIDE the fixed tracking dt (`_rk45_kernel_2d` prange; FSAL; metre-error controller vs `numerics.rk45_tol_m`; `rk45_h_min` floor → force-accept + one RuntimeWarning; substep cap `max(10⁴, 2·dt/h_min + 16)` → revert+OUTSIDE). Stages sample time via the same nested tinterp blend (`_interp_leastsq_core_tinterp`), so tinterp costs no stage materialization. **v1 fail-fasts** (integrator-level + pre-writer in tracking): 2-D only, element+leastsq only, no pchip/walk/em/m1. Unfused-style failure semantics (revert + failure_reason). Writer metadata `rk45_tol_m` (+`rk45_h_min` when set). Wrap-on-accept only when lon leaves [-180,180) (unconditional modulo cost ~1e-13° per substep). docs/time_integration.md §7.
- Failed particles: `status → OUTSIDE`, position reverted to pre-step, `failure_reason` recorded via `_update_failure_reason` (INTERPOLATION_FAILED vs OUT_OF_BOUNDS; unfused paths) and, since 2026-08, by every fused kernel via the `fr_out` scratch + `_merge_fused_failure` (all 13 kernels incl. the tinterp/pchip twins, the 2-D and 3-D barycentric kernels and fused 3D Euler; 44 stamp sites).
- **Alive-only optimization**: nearest-node/containment checks run only on alive/moved particles — steps get faster as particles die.
- Fused 2D Numba kernels for all three integrators; fused **3D Euler** kernel for z-level meshes (`w_interp` nearest/leastsq only); RK2 3-D on NODE-layout barycentric z-level meshes has its own FUSED kernel since 2026-08 (`_fused_rk2_step_3d_bary_{tinterp,pchip}` — per-vertex/per-interface inline time blends incl. 4-snapshot PCHIP, per-stage layer find, single-particle W nearest/barycentric, clamp in-loop; stage-1 anchor comes in EXACT from the batch search; under the default guard the stage-2/final anchors use the in-kernel exact search (`_grid_hash_nearest_exact`) and nothing is flagged; with `mesh.exact_nearest: false` they use **hybrid exactness** — an empty-hash-window anchor flags the particle WITH its stage position; the runner KD-heals those positions (`find_nearest_nodes`, the identical call the unfused path makes) and re-runs JUST the flagged subset through the same kernel with the anchor injected (`_run_fused_3d_with_heal`, `_FLAG_HEAL_ROUNDS=2`) — subset cost, no global work; the whole-field unfused splice (`_splice_exact_rerun`) is only the terminal fallback (its stage blends cost ~30 s/step on a zoom-10 mesh for even ONE flagged particle — the 2026-08 E2-scan '×24 wall' anomaly, diagnosed and fixed then). NO density-certificate gate: bit-identical on ANY mesh incl. high-zoom HEALPix where the certificate is denied; sigma/walk/w_interp∉{nearest,barycentric} (NB the CONFIG DEFAULT is leastsq — set `w_interp` explicitly to engage)/rk4 → unfused; measured ×1.30 at 1M particles × 196k nodes × K=70 through the real dispatch (development measurement, not recorded in the repository; lazy payload, 16 thr; grows with mesh/field size — per-particle scattered reads dominate both paths, hence not the 2-D-bary ×9); `_is_3d` now probes LazyLerpField PARENTS (was silently materializing u+w blends every 3-D step, 30-38 ms waste); `_apply_displacement` no longer re-wraps FROZEN positions (1-ULP/step drift of dead/NOT_RELEASED lons — pre-existing, fixed 2026-08); z-level runs skip the dead vel_end whole-field lerp/recon (clamp ignores eta there); bit-identical, pinned by test_fused_3d_bary.py (23 collected tests incl. coastal failures, empty-window class, hybrid splice); RK4 3D and all sigma 3D use the **unfused multi-pass** path — but each stage's u/v interpolation runs through the parallel vectorised kernels (stage-2+ positions fed via `_interp_uv_at` as a shallow stage state), so they scale across cores (no serial per-particle stage loop; bit-identical to the old serial path, pinned by `TestStageInterpParity` + `TestFullStep3DNodeBarycentricGolden`).
- `uv_interp` kwarg (default `"leastsq"`) threads through each step via `**kwargs`; the leastsq-math fused 2D/3D kernels are gated on `uv_interp == "leastsq"`. **`"barycentric"` on NODE-layout velocity with `vel_next` set (2-D, discrete AND temporal-interp runs, no recon, no walk elems) takes its own fused RK2/RK4 kernels** (`_fused_rk{2,4}_step_2d_bary_tinterp` → `_interp_barycentric_core_tinterp`: untouched bary geometry + the leastsq-twin nested per-VERTEX time blend, endpoint alphas 0/1 short-circuited like `_make_stage_vels`; kills the per-stage whole-node-field lerp — 4M-node RK4 step ~83→9 ms @8thr, mesh-size-independent), **with `mesh.exact_nearest: false` additionally gated on the grid-hash density certificate** (under the default guard they anchor through the exact in-kernel search and fuse on any mesh) (`mesh.grid_hash_dense_for_elements` — no element-bbox cell with an empty 3×3 window ⇒ the in-kernel widened anchor is provably bit-identical to the batch KD-healed one ⇒ fusing cannot flip verdicts; HEALPix polar rows FAIL it → unfused + one-time RuntimeWarning — the fused-vs-exact anchor divergence measurably killed polar particles, review 2026-08-16); everything else non-leastsq (element-layout bary, steady, walk, edge_leastsq) takes the unfused dispatcher path.

**Depth-linear u/v** (2026-10; `uv_vertical` `"level"` / `"layer_linear"`, docs/vertical.md §2.1, the interpolation kernels in [numerics.md](numerics.md) and `numerics/vertical_uv.py`):
- **Entry gate** `_check_depth_linear_entry(vel, mesh, uv_interp, integrator, *, vel_next, recon)` — FIRST in `euler_step`/`rk2_step`/`rk4_step`/`rk45_step`. A `"layer"` `vel` with `"layer"` companions returns after attribute reads only (`uv_vertical` of `vel`, `vel_next` and each recon snapshot via `getattr(…, "uv_vertical", "layer")` — no data, nothing of the mesh, no allocation: layer runs keep cost and bits; pinned by a `__getattribute__` guard in `tests/test_integrators_depth_linear.py`). A depth-linear `vel` is refused, in this order, for `rk45`, a mesh neither z-level nor sigma (`needs a z-level or sigma mesh`), a field without `w`, and a layout × `uv_interp` outside the table — node layout `barycentric` only, element layout `_DL_ELEMENT_UV_INTERP = ("leastsq", "edge_leastsq", "barycentric")` (the same tuple `tracking._LINEAR_UV_INTERP` imports), any other layout refused (a missing `uv_layout` counts as element, the `VelocityField` default); then the MIXTURE rule: every field the step receives (`vel`, `vel_next`, each recon snapshot) must hold the same placement, whichever side is depth-linear (a depth-linear companion of a layer `vel` is refused too), the message naming each field; then each field passes the record check unless `is_checked` — a `LazyLerpField`'s raw parents first (so a bad parent is named), each object once; an element-layout field is checked against the element table, which also refuses a z-level mesh without the element bottoms (`mesh.metadata["uv_data_last_elem"]` / `["elem_bed"]`). On a sigma mesh the table (both layouts) needs neither and serves `"layer_linear"` only, so a `"level"` field is refused by the record check (`numerics.md`, `depth_points`).
- **Stage depth** — every unfused stage hands its depth to the interpolator: `_interp_uv_at(..., zs=)` puts `zs` into the shallow stage state (layer interpolators never read `state.z`, so passing it leaves layer runs bit-identical); Euler reads the entry depth, RK2 `z` then `z_mid`, RK4 `z`, `z2`, `z3`, `z4`. **On a sigma mesh** (FESOM-C) the stage coordinate is the sigma fraction instead, `s = clip(z / H_p, 0, 1)` (`_sigma_frac_for_uv`, the vectorised `vertical_sigma._sigma_frac`, NaN kept), from the stage's depth in metres and its own column `H_p` (`_sigma_col_H` at the stage position and surface): Euler `z / H0` and RK2 stage 1 `z / H1` as a stage state `state.replace(z=s)` (they call `interp_fn` directly), RK2 stage 2 `zs = z_mid / H2`, RK4 `zs = z_k / H_out` for every stage in `_vel_at` (after `z = s·H_out`). The steps place stage k at `z_k = s_k·H_k`, so the read is the integrated `s_k` itself; the column of a stage enters it only through the rate `W / H`. W, the layers for W and the integration of `s` keep metres; the stage fields (`_EtaView`s of `_sigma_stage_field`) are passed as they are — they forward `uv_vertical` / `uv_layout` / `_dl_token` / `u` / `v` to the base field, which the entry check stamped (a blend or a PCHIP reconstruction holds its parents' token), so no stage re-checks. No fused kernel serves sigma 3-D (fused Euler gate `not is_sigma_3d`, fused node RK2 z-level only), so the depth-linear sigma path is the unfused one; PCHIP runs through the same stage functions (`tests/test_integrators_depth_linear_sigma.py`: each stage by hand; the convergence orders in `s` through `run_tracking` and the sigma mutants of the mutation pass: `tests/test_depth_linear_analytic.py`; its cost: `benchmarks/single_node/depth_linear_cost.py --vertical sigma`). A depth-linear stage SKIPS the layer lookup (`_compute_layers` is not called; `interp_layer`/`layer_arg = 0`, ignored by every depth-linear route — `_interp_barycentric_dl`, `_interp_leastsq_dl`, `_interp_edge_leastsq_dl`) — the per-stage branch tests the stage field's own `uv_vertical`. Node and element layout share this path: element-layout depth-linear RK2/RK4 (and Euler off the fused gate) always run unfused, the walk's `elems=` reaching `edge_leastsq` and element `barycentric` as for layer fields.
- **Fused 3-D RK2** — the gate is unchanged (node layout, barycentric, z-level, no walk elems, `w_interp` nearest/barycentric, not a lazy field at alpha 0); the runners pick the kernel by placement: `_fused_3d_uv_placement(site, named)` reads the one `uv_vertical` of every field the kernel reads (a lazy `vel`'s `vel_a`/`vel_b`, `vel`, `vel_next`; for PCHIP the step's `vel` — `rk2_step` passes it as `vel=` — and the four snapshots) and refuses a mixture; `_fused_3d_bary_field_checks(..., uv_vertical)` expects `K` rows for `"level"`, `K-1` otherwise; `_fused_3d_dl_table` record-checks every field the kernel reads (the PCHIP kernel reads only the snapshots) and returns `depth_points(...)`. `"layer"` → `_fused_rk2_step_3d_bary_{tinterp,pchip}`; depth-linear → `_fused_rk2_step_3d_bary_{tinterp,pchip}_dl` (the same kernel with the node table `p, last, bed` after `z_levels` and `(M, N)` u/v; no layer lookup for u/v; stage 1 at `zs[i]`, stage 2 at `z_mid`; the walls at depth of `_dl_node_wall` inside the cores `_interp_barycentric_core_{tinterp,pchip4}_dl`; W, anchors, flags, heal rounds, the terminal splice and the clamp untouched). The heal rounds re-run the same `_dl` twin; the terminal splice runs the unfused step, which reads the field with its own placement (`tests/test_fused_3d_depth_linear.py`, `tests/test_uv_vertical_matrix.py`).
- **Fused 3-D Euler** — the gate in `euler_step` admits `uv_vertical` `"layer"` and `"layer_linear"` (besides z-level, `uv_interp == "leastsq"`, `w_interp` nearest/leastsq); a `"level"` field is node layout, which `leastsq` does not evaluate, and never enters. `_run_fused_euler_3d` picks the kernel by placement: `"layer"` → `_fused_euler_step_3d` (raw `u[layer]` rows, unchanged); `"layer_linear"` → `_fused_euler_step_3d_dl`, the same kernel with the element table `p, last, bed` and the element areas after `z_levels` and `(M, E)` u/v, reading u/v at the particle's depth through `_interp_leastsq_core_dl` (walls and fallbacks included) — anchors, W for every alive particle before the u/v verdict, the move, the domain check and the clamp are the layer kernel's. `_fused_euler_3d_dl_table(vel, mesh, placement)` refuses a node-layout field (`_DL_LAYOUT`), record-checks a lazy field's `vel_a`/`vel_b` and the field (`_fused_3d_dl_table(..., layout="element")`) and requires u/v of shape `(M, E)` (no bounds checks in the kernel). Bit for bit the unfused Euler step (`tests/test_integrators_depth_linear_elements.py::test_fused_euler_equals_unfused`, walls and both `w_interp`; Numba off in a subprocess too).
- **Change both together**: `_fused_euler_step_3d` / `_fused_euler_step_3d_dl` duplicate the kernel body (a twin, so the layer kernel's body did not change); the fused node RK2 twins blend in depth in line, not through `vertical_uv.uv_at` — the full list of duplicated pairs is in [numerics.md](numerics.md) (*Change both together*, interpolate.py section).
- `_validate_time_aware_inputs` refuses `vel`/`vel_next` of mixed placement (attribute reads, no blend).
- Known pre-existing gap (layer path, not changed here): without Numba (`NUMBA_DISABLE_JIT=1`) the LAYER fused core `_interp_barycentric_core_tinterp_3d` blends float32 u/v in float32 (NEP 50 keeps `python float × np.float32` in float32), so its no-JIT result differs from the unfused float64 `_blend`; the depth-linear twin widens every stored value first (`_tinterp_point_uv`). Compiled runs are unaffected.

**Diffusion dispatch** — each integrator accepts `diffusion=DiffusionStepArgs(...)` (None → byte-identical no-diffusion):
- *split* (uniform Kh, any integrator): deterministic step, then `_apply_split_diffusion_kick` adds the Brownian kick; re-validates, reverts failures to OUTSIDE; 3D z **reclamped** after the horizontal kick against the new local bottom. `_apply_split_az_kick` runs LAST on the split path (all three integrators): vertical Az kick + reflective fold, z-only (no re-validation needed); receives `time_dir` and passes the SIGNED dt (`time_dir*dt`) to the loops, whose kernel takes |dt| for drift and noise — tracking's dt is always positive (same convention as the em/m1 drift kernels); short-circuits (same object) when az off/zero-source; `az_requires_field` (set by tracking when `var_az` configured) → payload without `vel.az` raises instead of silently degrading to az_const; 2-D vel + az → ValueError backstop; sigma + `vel.az` field → ValueError (v1); em/m1 + az_enabled args → ValueError backstop at the top of all three step functions (those branches never reach the kick).
- *combined* (em/m1 + Euler): `_apply_combined_em_step` *replaces* the Euler step with the full SDE step; Kh/∂K sampled at the start position. **3D raises NotImplementedError.**; fails fast for uv_interp != leastsq or node-layout velocities (the drift kernel is element-centre leastsq)
- *split_rk* (em/m1 + RK2/RK4): deterministic RK first, then `_apply_split_rk_em_kick`; `kh_eval_position` picks the Kh sample point; `_pick_kh_eval_vel` lerps Kh to `sim_time + dt` when temporal-interp info is available. One-time RuntimeWarning per `(seed, real_id, scheme)` — pragmatic extension, not a rigorous SDE scheme. **3D raises NotImplementedError.**

**Time-aware mode** — for time-dependent velocity, RK stages must evaluate `u(x, t + c_k·dt)`:
- Pass `vel_next=` (raw snapshot the step moves TOWARD — next file snapshot forward, **previous** one backward) + `dt_to_next=` (positive seconds to it); stages materialize `vel.lerp(vel_next, c_k·dt/dt_to_next)` via `_make_stage_vels`, or blend inline in the fused `_fused_euler/rk2/rk4_step_2d_tinterp` kernels — sampling `t ± c_k·dt` along the motion. The fused kernels take the RAW bracket pair + `alpha0` (from `LazyLerpField`) and a SEPARATE stage-target array (`u_t/v_t` = `vel_next`, which equals bracket-B forward but bracket-A backward — fusing those roles broke backward tinterp once, pinned by tests now); the nested blend `(1-αk)·((1-α0)·A + α0·B) + αk·T` is bit-identical to stepping on the materialized field. Plain fields pass `alpha0=0`, collapsing to the old arithmetic exactly. Both tracking paths pass the direction-correct neighbour (tinterp via `_resolve_time_bracket(..., direction)` / `_build_vel_payload(..., direction)`: on-snapshot backward queries bracket downward, so e.g. a backward start at the LAST snapshot gets a real bracket instead of a steady downgrade).
- Rules: both kwargs or neither; `dt <= dt_to_next` (else ValueError); shapes of u/v/eta/w must match; Euler accepts them; its velocity ignores them (on sigma meshes they give the column's surface at the end of the step).
- **Convergence caveat**: the *linear* (default) lerp between snapshots caps time-order at O(dt²) regardless of RK order — RK4 collapses onto RK2 at coarse `file_dt`. Remedies: `dt << dt_to_next`, denser file cadence, or `numerics.temporal_reconstruction: pchip` (below).
- **PCHIP temporal reconstruction** (`numerics.temporal_reconstruction = "linear" (default) | "pchip"`, `numerics/temporal_reconstruct.py`): a 4-snapshot monotone-cubic (Fritsch–Carlson) blend in time, replacing the 2-snapshot lerp. **Opt-in, byte-identical when `"linear"`.** Active only with `temporal_interp: true` (else a one-time inert `RuntimeWarning`). Tracking resolves a 4-snapshot stencil (`_resolve_recon_stencil` on top of `_resolve_time_bracket`; interior+consecutive only — first/last interval and cycle seam fall back to linear with a one-time warning) and passes `recon=(snaps4, times4, q_time, direction)` to `rk2_step`/`rk4_step`. **2D least-squares routes to FUSED 4-snapshot-cubic Numba kernels** (`_fused_rk{2,4}_step_2d_pchip` → `_interp_leastsq_core_pchip4`, blending the Fritsch–Carlson cubic inline per element via the `@njit` scalar twins `_fc_slope_scalar`/`_pchip_value_scalar` — no per-stage full-field materialization). **3-D RK2 on node-layout barycentric z-level meshes** (`w_interp` nearest/barycentric, no walk) routes to its own fused kernel `_fused_rk2_step_3d_bary_pchip` (`_run_fused_rk2_3d_bary_pchip`); every other 3-D, node-layout or barycentric case keeps the **unfused** path (`make_stage_vels_recon` → `reconstruct_pchip` per stage, at `q_time + direction·c·dt`); the fused 2-snapshot linear tinterp kernels are still bypassed when `recon` is set. The fused and unfused results agree element-for-element (pinned by `test_fused_pchip_matches_unfused`, RK2/RK4 × fwd/back); `_run_fused_2d_pchip` re-validates the bundle (4 finite strictly-increasing times, matching `direction`/`time_dir` sign, equal snapshot shapes, every stage time inside the central bracket) for parity with `reconstruct_pchip`, which raises. No new extrema PER COMPONENT (Fritsch–Butland weighted-harmonic slopes; does NOT preserve linear constraints such as zero divergence, rotation equivariance or window means — review 2026-09-22); works in 3D (per-element blend of u/v/w/eta/scalars; Kh NOT reconstructed). Result: under PCHIP, RK4 separates from RK2 at coarse cadence (test_temporal_reconstruction.py). Euler ignores `recon`. **failure_reason** IS stamped on the fused PCHIP path too (since 2026-08-16, candidate 7 — every fused kernel). **Unfused whole-field blends are PARALLEL** (TODO 6.7, 2026-08): `_pchip_blend4` routes large same-shape C-contiguous fields through the `prange` kernel `_pchip_blend4_flat` (per-element `_pchip_value_scalar` → bit-identical to the numpy expression, which remains the fallback), and `make_stage_vels_recon` dedups stage times (RK4's midpoint pair reconstructed once; exact float-key cache, stage fields are read-only). Measured: one core2-size blend 953→46 ms @8thr (×20; ×47 @32); RK4 stage set ~275 ms @8thr — the old ~5–6.6 s/step N-independent floor is gone (docs/performance.md §2). Remaining limitation: 23M-mesh 3D holds 4 snapshots (memory — crop the mesh).
