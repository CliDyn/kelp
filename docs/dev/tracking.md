## tracking.py
- `TrajectoryRecord` — list-based snapshot storage (`.append(state, t)`, `.to_arrays()`, `.set_release(lon, lat, z, time)`); `times` are float SECONDS (the same labels the writer gets, both modes). Velocity lists stay ALIGNED with the positions: the first snapshot carrying `u` (or `w`) NaN-backfills the earlier ones, a later snapshot without it appends NaN; `u/v` and `w` independent, no zero `w` invented in 2-D (`to_arrays` emits `vel_w` only when some snapshot had `w`); `release_lon/lat/z/time` `(P,)` in `to_arrays()` once set.
- `run_single_realization(mesh, ds, reader, init_state, mode, numerics, start_time_idx, n_steps=None, n_time_total=None, on_exhausted="stop", verbose=False, shared_cache=None, *, end_time_idx=None, writer=None, checkpoint_freq=0, temporal_interp=False, file_times=None, file_dt=None, sim_time_start=None, realization_id=0, start_step_i=0, sample_vars=None, sample_interp="leastsq", output_sample_vars=None, start_wet_streak=None, particle_offset=0)`:
  - **Discrete mode** (default): one file timestep per tracking step; still passes `vel_next + dt_to_next` to the integrator when `file_times` is available, so RK gets proper time-order.
  - **Temporal-interp mode**: blends velocity between adjacent snapshots; `dt` may be smaller than the file step; uses `file_times` when given, else reads the axis from `ds` (`extract_time_info`) or builds it from `file_dt`. The payload is a `LazyLerpField` (never a materialized full-field lerp): on the 23M global mesh the old eager payload cost ~380 ms/step (numpy) / ~84 ms (numba `_blend`) (development measurement, not recorded in the repository); the lazy payload is ~1 µs + per-field blends only for consumers that read them.
  - `on_exhausted="stop"` breaks at the file boundary; `"cycle"` wraps via `% n_time_total`.
  - **Record clock (output format 2)**: the record after global step `g` is labelled `T_g0 + (g+1)·dt·direction` in seconds since the forcing's first RAW record (the `extract_time_info` origin; the `mean` shift moves values, not the origin), `T_g0` = the start of global step 0 (`_record_clock_origin`): interpolated → `t_first − start_step_i·dt·direction`, `t_first` = `sim_time_start` or `file_times[start_time_idx]` (exactly the `sim_time` init); discrete → the time of the record where global step 0 started, `_index_to_sim_time(start_time_idx − start_step_i·direction, axis, n_time_total, on_exhausted)` with `axis` = `file_times` or, for a direct caller that passed none, the dataset axis `_check_discrete_dt` reads (unshifted) — anchoring on the segment's own start record made the labels depend on the chain cuts when the spacing differs from `dt` within the check's tolerance; `sim_time_start` IGNORED in discrete mode (the reads follow `start_time_idx`); no axis → `(start_time_idx − start_step_i·direction)·dt` (then `on_axis` False → no epoch). `start_time_idx` must be whole (a float such as `start0 + n·time_dir` is cast; 2.5 → ValueError). The internal `sim_time` accumulator is untouched → positions bit-identical; labels are chain-cut invariant (a resume passes the SAME shifted `file_times` and, discrete + `cycle`, the UNWRAPPED start index — the checkpoint's `restart_file_idx` stores the unwrapped index in discrete mode, so `file_idx + direction` resumes too). Discrete labels are the particle clock: they may drift from the record stamps by `_check_discrete_dt`'s tolerance per step. At start (before `TrajectoryRecord()`): `writer.set_time_units(*readers.time_axis_epoch(ds))` when on-axis and the axis has an epoch, else `units = "seconds"` + `NO_EPOCH_NOTE`; `cycle_period` under cycle (axis span + last interval, or `n_time_total·dt`); `set_trajectory_ids(particle_offset + arange)` when the offset ≠ 0; `writer.write_release(*_release_arrays(state, mesh, t_g0, dt, direction))` and `record.set_release(...)` — EVERY call/segment. Release positions are filled from the state after the init periodic fold when `start_step_i == 0` and `state.release_lon is None`; a resumed state without them → one RuntimeWarning, NaN positions (release_time still computed). `_release_arrays` un-rotates to geographic with the record rule. Record path: `time_val = t_g0 + (global_step_i + 1)·dt·direction`, then `_geo_view_for_record` (rotated mesh: `vel_u/vel_v` un-rotated at the step's START position, where the integrators evaluate them — rk45 at the end; the end position turned the vector by the frame's change of direction along the step) → `mask_dormant_for_record` → `mask_inactive_velocity(rec_state, prev_status)` → in a backward run `u/v/w` negated (the integrators carry `time_dir·velocity`; format 2 writes the FLOW velocity, same sign both directions — owner's decision 2026-10-13; format 1 wrote the time-reversed value).
  - Shared `_VelCache` avoids re-reading snapshots (critical when cycling few timesteps on big meshes).
  - Downgrades RK stages to steady velocity when `dt > dt_to_next` (start-between-snapshots, end-of-range) — one RuntimeWarning per realization.
  - `verbose=True` → per-step ms timing + first-25%/last-25% slowdown comparison + orchestration-level phase breakdown per step `(io= step= [beach=] rec=)` and a mean-phases summary (TODO 6.6; kernel-internal phases are not separable in the fused kernels; zero cost when verbose off).
- Time helpers: `_resolve_time_bracket` (pure index/time math), `_build_vel_payload` (I/O via cache + lerp; forwards `diffusion=` so the cache reads Kh fields), `_interp_velocity_at_time` (back-compat 2-tuple).
- Diffusion helpers: `_resolve_composition(diff_cfg, integrator_name)` (also used for writer metadata, so the two always agree), `_compute_default_dres_m(mesh)`.
- **Beaching** (config-driven via `numerics.beaching`; dormant = one boolean per step): post-step hook `_apply_beaching_hook` (after step_fn, before sim_time advance) — (1) context-gated on_failure remap: newly ALIVE→OUTSIDE remapped to BEACHED iff anchor `H_raw < zone` OR anchor element coastal (the gate is anchor context by design — it predates the fused kernels stamping failure_reason (2026-08); codes are cleared on remap/resuspension so the field keeps cause-of-death semantics); deep open-boundary exits stay OUTSIDE; (2) `evaluate_beaching` criteria + resuspension. Freeze costs nothing: integrators move only ALIVE. Topology built when coastal_element OR stochastic in criteria (zone-OR degrades silently otherwise — tracking-level test pins it). Containment runs on `alive|beached|newly_failed` subset (8.8× cheaper at 90% dead (development measurement, not recorded in the repository)). `wet_streak` is loop-carried, checkpointed (`restart_wet_streak`, both backends; `load_restart` returns it; `start_wet_streak=` resumes), RNG keyed by global step_i → restart-bitwise. `beaching_*` writer metadata only when enabled. eta for drying comes from the step payload `vel.eta` (start-of-step / lerped) — never the mesh.
- **Field sampling** (`sample_vars=`, `sample_interp=` kwargs; config-driven via `run_tracking`): sampled ONLY at the existing post-step record points via `_sample_record_fields` (uses post-step `state.nearest_node` + the SAME field's eta). Discrete mode → the record at the END of the step (`file_idx + direction`, wrapped under cycle; already in the cache as the step's target) so the instant equals the label (output format 2); no next record (last step of a `stop` run at the forcing's end; backward at record 0) → the start-of-step `vel`, and the sampled vars' `comment` says so (format 1 sampled start-of-step always — a one-record lag); temporal-interp → scalars+eta **re-lerped to the post-step `sim_time`** (= recorded timestamp) via the cache; end-of-range fallback to in-hand `vel`. `_VelCache.get`/`_build_vel_payload` forward `sample_vars` conditionally (stub readers without the kwarg keep working). run_tracking: fail-fast probe `read_scalar_fields` at start idx before any I/O/writer creation + attrs map → `sample_var_attrs`; `sample_interp` in writer metadata only when sampling on.
- **u/v interp fail-fast** (`_validate_uv_compat(uv_layout, uv_interp, uv_vertical_option="layer", *, mesh=None)`): node layout + `uv_interp="leastsq"` or `"edge_leastsq"` → ValueError (element-centre math), in both modes; with `mode.uv_vertical: linear` also the layout table and the element mesh (`mode.uv_vertical` below). Two guards: `run_tracking` metadata-only pre-writer probe (`reader.probe_uv_layout`, dims/sizes, no data load) + a step-0 backstop in `run_single_realization` (covers readers without the probe + direct callers); with the option `linear` a third, the entry probe of `run_single_realization` (below). `uv_interp` in writer metadata only when ≠ `leastsq`; `edge_leastsq_bc` metadata + `build_elem_neighbors` pre-warm only when `edge_leastsq`. `edge_leastsq_bc` threads config → step kwargs → `get_interpolator` (track_particles takes it as a kwarg too). Also pre-writer: em/m1+euler (combined) × non-leastsq uv_interp → ValueError before the writer exists.
- **`mode.uv_vertical`** (2026-10; `"layer"` default | `"linear"`; docs/vertical.md §2.1, docs/configuration.md §2):
  - *Refusals* `_check_uv_vertical_option(option, *, fdrift3d, mesh, uv_interp, reader)` — in `run_tracking` right after `load_mesh` (before the dataset is opened) and again at the entry of `run_single_realization` (direct callers, before any read): the value; for `"linear"` 3-D, a z-level mesh, a `uv_interp` that appears in the layout table `_LINEAR_UV_INTERP = {"node": ("barycentric",), "element": integrators._DL_ELEMENT_UV_INTERP}` (`leastsq`, `edge_leastsq`, `barycentric`; the layout is not known yet, so the message names the whole table), and a reader whose u/v are layer-centred (`getattr(reader, "native_uv_vertical", "layer") == "level"` → refused: level data are always depth-linear). The layout is checked where it is known, by `_validate_uv_compat(uv_layout, uv_interp, uv_vertical_option, mesh=mesh)`: the layout must be in the table and the interpolator in its row (`_linear_option_layout_error(uv_layout, uv_interp=None)`: an unknown layout, or the row's interpolators and the one given), and element layout then calls `_check_linear_element_mesh(mesh)` — no element bottoms (`mesh.metadata["uv_data_last_elem"]` or `["elem_bed"]` missing: the message names `mesh.metadata["meshpath"]` ("this mesh" without one), the missing keys, "the mesh diagnostic has neither nlevels nor zbar_e_bottom (an ASCII mesh directory never has them)" and the fix — the run's full `fesom.mesh.diag.nc`, or a re-extraction with `utils/extract_fesom_region.py`) or ice-shelf cavities (`mesh.metadata["elem_ulevels"] > 1` anywhere: the count, the first element and its `ulevels`; not supported yet). Sites: the pre-writer probe of `run_tracking` (with `mesh=`); the ENTRY probe of `run_single_realization` — option `linear` and a reader with `probe_uv_layout` only, right after `_prepare_dataset`, metadata only, so a direct call is refused before any read and before anything is written to a caller's writer (readers without the probe get the refusals at the marking and the step-0 guard); the step-0 backstop (with `mesh=`); and the cache marking. Option off: `_validate_uv_compat` returns after the node rule, nothing else runs.
  - *Marking* `_mark_depth_linear(vel, option, mesh, *, record)` — EVERY store site of `_VelCache` (the per-record read, each record of a prefetch window, the shared-cache path — outside its fail-open `try`, a refused record is a data error, not a shared-layer one) passes its field through it, so the cached object is the marked and checked one: option `"layer"` + `"layer"` field → the same object, untouched (no copy, no check: default runs stay bit-identical); `"linear"` + `"layer"` field → a SHALLOW copy marked `"layer_linear"` (`dataclasses.replace`; a lazy blend → a new `LazyLerpField` over marked parents; the same arrays), refused for a 2-D field and a layout other than node or element (an element field passes `_check_linear_element_mesh(mesh)` first); `"linear"` + `"layer_linear"` → returned as is (idempotent); a `"level"` field → kept with `"layer"`, refused with `"linear"`; a `"layer_linear"` field with `"layer"` → refused (a field marked by another run's option). A depth-linear result is record-checked unless `is_checked` for this mesh's table.
  - *Record labels*: the cache names a record by its GLOBAL index (`"time index N"`); the HEALPix reader's own raw-record check names the dataset-LOCAL index (a prefetch window counts from its start) plus the time stamp (`readers/healpix.py:_record_label`).
  - *Shared cache*: `_flatten_vel` puts `uv_vertical` into the snapshot's meta and `_assemble_vel` restores it; the record-check token never travels (an attached field is checked again in its own process). The namespace tag includes `asdict(config.mode)`, so runs with and without the option never share snapshots.
  - *Output*: the global attribute `uv_vertical = "linear"` is written ONLY when the option is on (`run_tracking` metadata; `run_single_realization` for a caller-supplied writer) — option-off files carry no new attribute (byte-identity); the shard concat compares it like every global attribute.
  - *One rule per trajectory*: `_validate_restart_uv_vertical(restart_value, mode)` — the caller-driven resume check beside `_validate_restart_frame` (`load_restart(...)["uv_vertical"]`, `None` = `"layer"`; a mismatch raises naming both rules). `_check_writer_uv_vertical(writer, option)` — at the entry of `run_single_realization`, before anything is written; read-only: a writer carries the rule an earlier segment BOUND to it (`TrajectoryWriter.bound_rule("uv_vertical")`), else its `uv_vertical` attribute (`TrajectoryWriter.global_attr`: construction metadata + `set_global_attr`), else `"layer"` once it holds records written by other code (`n_obs > 0`); a fresh writer takes any rule; writers without `global_attr` are not checked. `_bind_writer_uv_vertical(writer, option)` — right before the segment's FIRST write of any kind (the provenance attributes, then records and checkpoints): `writer.bind_rule("uv_vertical", option)`, in memory only (option-off files get nothing new), the first binding kept — so a segment that wrote only a checkpoint (no record) binds too. `TrajectoryWriter.open()` creates a new file on both backends and resets both (`global_attr` back to the construction metadata, no bindings), so a reused writer object starts fresh.
  - *`_apply_max_levels(mesh, mode, verbose=False)`* — the `max_levels` cut, shared by `run_tracking` and `run_single_realization`: the uncut table is stored once in `mesh.metadata["sigma_full"]` and every cut is taken from it, so repeated calls with different limits on one mesh (direct entries) each get their own table, `max_levels: None` restores the full table of a mesh cut earlier, and a call that leaves the table as it is keeps the very array object (a depth-point table built for it stays valid). A table replaced by someone else since (not a prefix of `sigma_full`) becomes the new full one. `run_single_realization` applies it for a depth-linear run (the option, or a level reader) AND for any mesh this helper cut earlier — also for layer runs: the FESOM2 reader trims its arrays by `mode.max_levels`, not by `mesh.sigma.size`, so a direct entry with another limit on a mesh cut before would otherwise read arrays and levels of different depths. Layer runs on an uncut mesh keep the historical behaviour (no cut there). `max_levels < 2` in 3-D raises as before.
  - *`_prepare_dataset(reader, mesh, ds)`* (defined in `readers/__init__.py` since 2026-10-19, imported into `tracking` under the same name — `kelp info` uses it without importing the integrators) — the optional reader hook `prepare(mesh, ds)`, run at EVERY call: the engine keeps no record of what a mesh was prepared for (no dataset token, no level-table, bed or reader stamp) and writes nothing into `ds.attrs` or `mesh.metadata` for it, so a dataset switch (A → B → A), a dataset saved and reopened or `copy()`-ed, a `max_levels` re-cut, a replaced `mesh.depth` (also on a shallow copy) or another reader all get their own `prepare`. `run_single_realization` calls it at its entry, after `_apply_max_levels` (the hook sees the levels in use): once per realization. `run_tracking` calls it once more, right after `open_dataset`: the sampling and dry-mask probes read the dataset on the mesh, and the writer of each realization is opened BEFORE `run_single_realization` runs, so this call is what makes a refusal of the hook come before any output file exists. Calls per run: `run_tracking` 1 + R for R realizations (2 for one), a direct `run_single_realization` or `track_particles` 1, `kelp info` 1. Cost: one hook per call — the FESOM 1.4 hook reads one record of each variable, 0.41 s per call on the published LR mesh (127k nodes, 46 levels; `benchmarks/single_node/fesom14_lr_cost.md`); a hook that assigns a new declaration also costs one table rebuild and one record re-check of each field still cached (milliseconds at that size). A hook that raises leaves nothing behind in the engine (the next call simply runs it again). Readers without the hook: nothing happens (option-off runs unchanged). Never written to the output.
  - `mesh.metadata` is SHARED by shallow copies of a mesh (`copy.copy`, `dataclasses.replace`): a cut or a declaration (`uv_data_last`, also the engine's snapshot of it) set on one is seen by the other — harmless for the declaration, since every entry prepares again; the depth-point tables (`mesh._uv_depth_points`) are copy-on-write instead.
- **Readers that resolve their record times** (2026-10; `readers._READER_RESOLVES_TIME = ("fesom14",)`, docs/io_and_time.md §3): `run_tracking` calls `readers._time_option_kwargs(config)` right after `get_reader`, before the mesh is loaded — the `data.time_stamp` / `time_window` / `time_offset` keys that are set become `open_dataset` kwargs (merged into the same `_extra` dict as `diffusion=`; only when set, so other readers' signatures are untouched); likewise `readers._dry_mask_kwargs(config)` adds `dry_mask_var=` for such a reader that opens only the consumed variables (`_READER_OPENS_CONSUMED`) when beaching is enabled with `beaching.dry_mask_var` set (the pre-writer dry-mask probe then finds it in the dataset; it reaches the output only through `mode.sample_vars`); set for any other mesh type → `TypeError` naming every key and the mesh type; `data.time_averaging` set for such a reader → `ValueError` pointing to the stamp options. The reader's `ds.time` already holds the resolved instants, so the `time_averaging` block neither warns nor calls `_shift_to_midpoints`: `time_avg = readers.RESOLVED_BY_READER` (`"resolved_by_reader"`, the output's `time_averaging` attribute, compared by the shard concat like any attribute), and one summary line `Record times: resolved by the reader from <source>[, data.time_offset … applied]; first …, last …` (`readers._describe_record_times`) prints whatever `verbose`. `start_date` resolves against those instants (a daily mean at 12:00; monthly means need `temporal_interp`, `_check_discrete_dt` refuses their irregular spacing). Pre-writer refusals for `mesh.type == "fesom14"`: `em`/`m1` diffusion (FESOM 1.4 output has no Kh fields; uniform Kh works), `beaching.use_eta` when `ds.attrs["fesom14_has_eta"] == 0` (no sea surface in the files; the message names `mode.var_eta` or `zos`).
- **Edge-walk tracking** (`numerics.elem_search: "walk"`; docs/localization.md §7): `run_single_realization` seeds `state.elem` with ONE global search (config authoritative — `local` strips carried elems, restart resumes warm); the unfused step paths re-validate the carried elems by WALKING at every evaluation position (`_walk_update_elems` — warm hints, never trusted blindly: kicks/restarts may have moved particles), hand the pre-validated elements to barycentric/edge_leastsq via `elems=` (`UV_INTERP_USES_ELEMS`; internal search skipped), use the walk for the final domain check, and carry the updated elems (failed particles revert elem with position). Fused leastsq kernels ignore the walk (one-time RuntimeWarning on that combo); diffusion-kick revalidation keeps the old machinery (elem stale-by-kick self-corrects next step). Verdicts == local, pinned bitwise by test_edge_walk.py; `elem_search` in writer metadata only when `walk`.
- **Rotated frame** (dormant when `mesh.rotation_angles is None` = byte-identical, same object returned): `_maybe_rotate_seeds(state, mesh)` rotates user/geographic seeds INTO the mesh frame at the **two user entry points** (`run_tracking` seed load + `track_particles`) — `run_single_realization` treats its init_state as already in-frame (restarts arrive rotated). `_geo_view_for_record(state, mesh)` un-rotates positions + `vel_u`/`vel_v` onto a **COPY** at record time (internal state stays rotated; sampled scalars stay frame-rotated — frame-invariant). `state.release_lon/lat` (and `restart_release_*`) live in the mesh frame; `_release_arrays` un-rotates them for the `release_*` output variables. `_validate_restart_frame(restart_angles, mesh)` — caller-driven resume recipe (`load_restart` → validate → `run_single_realization`), raises on frame mismatch. Checkpoints pass `rotation_angles=mesh.rotation_angles`; writer metadata `rotation_angles` only when rotated. **Output is always geographic.**
- `run_tracking(config, verbose=False, output_path=None, checkpoint_freq=None, temporal_interp=None)` (`None` = take the value from the config) — loads everything from config, runs `num_runs` realizations (file suffix `_rN` for multi-run); auto-detects dt; in discrete mode refuses a `dt` unlike the record spacing (`_check_discrete_dt`, 2026-09-24, pre-writer here AND in `run_single_realization`, which reads the axis from `ds` when a direct caller passes none — for the check only in discrete mode (passing it on would switch on the discrete `vel_next`), for the run itself in temporal-interp mode (it used to raise 'no usable time axis') — `track_particles`/chain drivers cannot bypass it: regular axis → `max(0.1 s, 1e-3·file_dt)` jitter allowed; IRREGULAR record times (calendar months, a gap) → refused; the decoded axis decides whenever it has ≥ 2 record times and any positive spacing (one repeated stamp → irregular, refused) — `numerics.file_dt` counts only for a file without one or with all stamps equal (it let monthly stamps pass until 2026-10-04); `run_single_realization` reads the dataset's axis whenever no `file_times` are passed, no single dt fits them, use temporal_interp; < 2 records or no axis → no check — the step read one record per step while moving the particles by dt, so the forcing ran at another speed; the old printed notice claimed 'effective dt = file_dt'); prints a diffusion summary line whenever diffusion is enabled (like the sampling, beaching, uv_interp and dt lines, regardless of `verbose`); writer metadata gets `diffusion_*` attributes with the *resolved* composition.
- `track_particles(mesh, ds, reader, lon0, lat0, z0=None, start_time_idx=0, n_steps=None, on_exhausted="stop", dt=900.0, time_dir=1.0, integrator="euler", output_freq=1, mode=None, *, end_time_idx=None, writer=None, checkpoint_freq=0, temporal_interp=False, file_times=None, file_dt=None, w_interp="leastsq", uv_interp="leastsq", edge_leastsq_bc="freeslip", elem_search="local", Dmin=0.5, z0b_min=0.1, rk45_tol_m=1.0, rk45_h_min=None, periodic_lon=None, periodic_lat=None, diffusion=None, realization_id=0, start_step_i=0, exact_nearest=True, grid_hash_cell_rule="occupancy", sample_vars=None, sample_interp="leastsq", particle_offset=0)` — simple functional API (builds a `NumericsConfig` from the keywords and calls `run_single_realization`).

## cli/main.py
`kelp` console script (`[project.scripts]`; install with `pip install -e .`, not on PyPI).
```bash
kelp info config.yaml      # mesh stats + time range, no tracking
kelp run  config.yaml -o out.nc --temporal-interp --checkpoint-freq 50 --seed 42 --verbose
```
- `info` catches mesh-load / reader-registry / dataset-open failures → clean stderr + rc 1.
- `info` opens the dataset as a run does (2026-10-19): `open_dataset(ncinput, v_path=ncinput_v or None, w_path=ncinput_w or None, mode_cfg=config.mode, **readers._time_option_kwargs(config), **readers._dry_mask_kwargs(config))` — the separate v/w paths for EVERY reader (before, only `ncinput`; a FESOM2 single-file `ncinput` with `ncinput_v`/`ncinput_w` now merges and aligns them as the run does, so a misfit is refused here too), the stamp options for a reader that resolves its record times (a refused key or `time_averaging` → stderr + rc 1 before the mesh is loaded); then `readers._prepare_dataset(reader, mesh, ds)` (a refusal → `the dataset … does not fit the mesh: …`, rc 1) and, for such a reader, one `record times …` line (`readers._describe_record_times`). It imports `config`, `mesh`, `readers` and the reader only: not `tracking.py` nor the integrators (`tests/test_cli.py::TestCliInfo::test_info_imports_no_tracking_loop`, a fresh interpreter).
- **Gotcha**: `--temporal-interp` and `--checkpoint-freq` default to `None` (not False/0) so YAML config flows through when the flag is absent. `--seed` overrides `numerics.diffusion.seed` via `dataclasses.replace` (validation runs).
